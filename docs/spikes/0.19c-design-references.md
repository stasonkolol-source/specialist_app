# Спайк 0.19c: PNG-эталоны артбордов

**Итог: способ работает, план Б (скриншоты холста) не нужен.** 71 артборд и `Main.dc.html` рендерятся офлайн в Docker-образе Playwright за ≈ 3 с. Остаётся визуальная сверка владельцем на 5 артбордах — список ниже.

## Задача

Экранным шагам (с 1.5a) нужен эталон «как на макете» для каждого артборда `design/project/*.dc.html`. Артборды не открываются как есть:

- `<script src="./support.js">` — скрипт отдаёт хост холста design-canvas, в репозитории его нет;
- `<link rel="stylesheet" href="/_blob/<id>">` — ссылка на `ui.css` в хранилище холста;
- шрифты Onest и Unbounded — с Google Fonts.

## Способ

Playwright в образе `mcr.microsoft.com/playwright:v1.63.0-noble` открывает артборд на выдуманном origin `http://design.local` и отвечает на все запросы сам (`page.route`):

| Запрос | Ответ |
|---|---|
| `/project/<файл>.dc.html` | файл из `design/project/` |
| `/project/support.js` | заглушка `packages/ui-web/design-refs/support-stub.js`: переносит `<helmet>` в `<head>`, `<x-dc>` — обычный блок |
| `/_blob/*` | `design/ui.css` |
| `fonts.googleapis.com/css2?…` | `@font-face` из `@sosed/design-tokens` (`fonts.generated.css`) с url на `/fonts/…` |
| `/fonts/@fontsource/…woff2` | woff2 из `@fontsource/onest` и `@fontsource/unbounded` (те же подмножества, что в приложении) |
| всё остальное | отказ; тест падает, если артборд пытался уйти в сеть |

Снимается элемент `.scr` — ровно ширина × высота из `canvas.json` (тест сверяет размер). `Main.dc.html` (1440 × 1280, эталон галереи ui-web) снимается целиком в `design/reference/gallery/Main.png`, отдельно от 71 экрана. Тёмные артборды (D03, D13, D30) уже содержат `.theme-dark` — отдельная настройка не нужна. Масштаб 1× — как у скриншотов реализации (390 × 844 в e2e).

## Команды

- `pnpm design:render` или `make design-render [GREP=S03]` — PNG в `design/reference/` (71 файл) и `design/reference/gallery/Main.png`. `GREP` фильтрует по заголовку и имени файла артборда.
- `make design-compare [GREP=S03]` — отчёт «эталон рядом с фактом» в `packages/ui-web/test-results/design-compare/index.html` (открывается как файл, сеть не нужна). Факты: скриншоты галереи ui-web (light, ru) рядом с `Main`, скриншоты экранов `apps/tma/e2e/__screenshots__/<КОД>-….png` — рядом с артбордом с тем же кодом (появятся с 0.21b).

## Что проверено

- 72 из 72 артбордов отрендерены; размеры `.scr` совпадают с `canvas.json`.
- Ни одного сетевого запроса наружу; все шрифты, которые артборд использует, загружены без ошибок (`document.fonts`).
- Визуально (агент): S03, D30, B1, Main — вёрстка, шрифты Unbounded и Onest, иконки, тёмная тема как на холсте.
- Отчёт сравнения работает на галерее: `make design-compare GREP=Main` — эталон и 15 разделов галереи.

## Находки

- Скан артбордов нашёл две иконки, которых нет в таблице SPEC §3: `play` (видео в портфолио, S08 и S10) и `bag` («Вещи», D03 и S58). Они добавлены в `ui-web` отдельным списком; в SPEC их стоит дописать при следующей версии.
- В `Main.dc.html` активная кнопка-иконка «в избранном» — залитое красное сердце; в `IconButton active` сейчас красный контур. Решение — при сверке галереи владельцем.
- Шрифты self-host совпадают с Google Fonts по начертаниям и подмножествам; у Onest дополнительно подключено `math` ради «≈» и «→» из текстов макетов — без него знак рисовался бы системным шрифтом.

## Ограничения

- Эталон — статичное состояние артборда: ховеры, фокус и анимации не снимаются.
- Пиксельного совпадения эталона и реализации не будет (сглаживание, округления layout); отчёт — для глаз, а не для автоматического diff.
- `design/reference/` — производные файлы: при новой версии макета их пересоздают командой, а не правят.
