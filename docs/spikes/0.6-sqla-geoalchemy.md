## Находки — правила для кода

1. **GeoAlchemy2 по умолчанию создаёт свой GiST-индекс** `idx_<таблица>_<колонка>` на каждую колонку `Geography`/`Geometry` (`spatial_index=True`). Вместе с явным индексом по нашему naming convention получается дубль: лишняя запись на каждый INSERT/UPDATE и случайный выбор индекса планировщиком (из-за этого проверка плана «мигала»). **Правило:** типы колонок в `platform/db` (шаг 0.7b) создают `Geography`/`Geometry` с `spatial_index=False`, индекс объявляется явно с именем `ix_<таблица>_<колонка>`. Тест `test_no_duplicate_spatial_indexes` фиксирует это.
2. **Роль `app` не может `TRUNCATE` и создавать временные таблицы** — так задумано bootstrap'ом (права по умолчанию: только DML; `TEMP` отозван у `PUBLIC`). Очистка в тестах — `DELETE`, схемы и таблицы создаёт `migrator`.
3. **Статистику собирает владелец таблицы.** `ANALYZE` под ролью `app` пропускается без ошибки (нет прав владельца). Для тестов с проверкой планов — `ANALYZE` под `migrator`; в проде — автовакуум.
