## Итог

Файл идёт с телефона прямо в хранилище по presigned-ссылкам, web его не проксирует. Схема из [ARCHITECTURE §10.2](../ARCHITECTURE.md) работает на Garage и в Chrome. Прогон на iPhone и Android ждёт телефонов владельца ([K8](../OWNER_CHECKLIST.md)).

| Проверка | Garage (тест) | Chrome, локальный стенд | iPhone, Telegram | Android, Telegram |
|---|---|---|---|---|
| Фото целиком: presigned PUT → HEAD (размер, тип) | ✓ | ✓ | ожидает K8 | ожидает K8 |
| 3 файла разом, включая HEIC | — | ✓ (HEIC с пустым `type`) | ожидает K8 | ожидает K8 |
| Камера (`capture=environment`) | — | — | ожидает K8 | ожидает K8 |
| Видео через multipart (20 MB в Chrome; на телефоне — больше 50 MB) | ✓ | ✓ (3 части) | ожидает K8 | ожидает K8 |
| Файл другого размера или типа по той же ссылке | ✓ 403 | — | — | — |
| Просроченная ссылка → новая ссылка и повтор | ✓ 400 | ✓ (тест загрузчика) | ожидает K8 | ожидает K8 |

| Превью по presigned GET (CSP `img-src`, `media-src`) | ✓ | ✓ | ожидает K8 | ожидает K8 |

## Решения — правила для 2.1

1. **Подпись PUT включает `Content-Type` и `Content-Length`.** Garage отвергает файл другого размера или типа ещё до записи (403 `Invalid signature`). Браузер ставит `Content-Length` сам по размеру `Blob`, поэтому клиенту ничего делать не нужно. Так presigned PUT закрывает и то, чего нет у R2: presigned POST с `content-length-range`. `HEAD` после загрузки остаётся второй проверкой. То же поведение R2 проверяем в [0.26](../DEVELOPMENT_PLAN.md).
2. **Порог multipart и размер части — 8 MiB** (`PART_SIZE`; минимум S3 — 5 MiB, кроме последней части). Каждая часть подписана со своим `Content-Length`. Клиент грузит по 3 части параллельно (`PARALLEL`), а ETag каждой части читает из ответа. Поэтому в CORS бакета нужен `ExposeHeaders: ETag`: без него загрузчик падает с понятной ошибкой, а не собирает файл из пустых ETag.
3. **Просроченная ссылка.** Garage отвечает 400 `Date is too old` (проверено), R2 по документации — 403. На 400 и 403 клиент просит у backend новую ссылку на ту же часть и повторяет. На обрыв сети (status 0) и 5xx клиент повторяет ту же ссылку с паузой 1, 2, 4, 8 с (5 попыток). Задача помнит план и готовые части: ручной «Повторить» догружает только недостающие. Если часть не загрузилась после всех попыток, остальные части останавливаются. «Отменить» отменяет multipart на сервере и забывает план, и следующий «Повторить» начинает загрузку заново.
   **`complete` идемпотентен.** Ответ на первый `complete` может потеряться: телефон ушёл в офлайн, или botocore повторил запрос по таймауту. Повтор тогда получает `NoSuchUpload`, хотя объект уже собран. `S3Storage.complete_multipart` в этом случае проверяет `HEAD` и считает загрузку завершённой. Ключ у каждой загрузки свой, поэтому объект по ключу — наш. В 2.1 к этому добавится сверка размера с планом.
4. **HEIC.** Android WebView отдаёт HEIC с пустым `File.type`: тип определяется по расширению, и на клиенте, и на backend. iOS при выборе из галереи с `accept="image/*"` может сам перекодировать HEIC в JPEG. Какой файл приходит на самом деле, покажет прогон на iPhone: страница пишет в лог `type` и размер каждого выбранного файла. Worker из 2.2 должен читать HEIC (pillow-heif) в любом случае.
5. **CSP.** PUT и превью идут на S3 API хранилища, а не на CDN. Поэтому его origin нужен в `connect-src`, `img-src` и `media-src`. Переменная `TMA_STORAGE_ORIGINS` в `apps/tma/.env`: в prod — `https://<account>.r2.cloudflarestorage.com`, в dev — туннель Garage (его пишет `make tunnel`). Без неё браузер молча режет PUT, и загрузчик видит «обрыв сети».
6. **boto3.** `request_checksum_calculation=when_required`: иначе новые boto3 добавляют в подпись заголовки CRC, которых браузер не шлёт. Ссылки подписывает отдельный клиент на `S3_PUBLIC_ENDPOINT_URL`: хост входит в подпись SigV4 и должен совпадать с тем, куда пойдёт телефон. Служебный клиент (HEAD, multipart) ходит по внутреннему `S3_ENDPOINT_URL`. Сетевые вызовы — через `asyncio.to_thread`.
7. **Загрузчик на клиенте.** Рекомендация для 2.1 — свой загрузчик из спайка (≈200 строк, `XMLHttpRequest` ради прогресса отправки, покрыт тестами), а не Uppy `@uppy/aws-s3` из [ADR-0012](../adr/0012-mini-app-frontend-and-mobile-path.md). Причины: он уже работает с нашим API, не добавляет десятки КБ в бандл и не требует UI Uppy. Решение фиксируется правкой ADR-0012 в 2.1.
8. **Ошибки хранилища.** 4xx от S3 (`InvalidPart`, `NoSuchUpload`, `EntityTooSmall`) → 422 клиенту, а код S3 уходит в лог. 5xx не маскируются под ошибку клиента: они остаются 500 и попадают в Sentry. В 2.1 5xx отображаются в `external_service_unavailable` (503) по ADR-0020 §9.
9. **Только dev — с отказом по умолчанию.** `APP_ENV` по умолчанию равен `dev`, поэтому образ backend задаёт `APP_ENV=production`. Stage в 0.25 переопределяет его на `stage`. Без этого релизный образ, запущенный без `APP_ENV`, открыл бы `/__spike` и dev-команды CLI.
10. **Ключи и права.** Ключ объекта создаёт backend: `<префикс>/<UUIDv7>.<расширение>`. Клиент не выбирает путь; чужой ключ — 403. В 2.1 ключ привязывается к записи `media` и назначению (`purpose`), а квоты и лимиты по назначению проверяются до выдачи ссылки.

## Как повторить на телефоне (K8)

1. `make dev` — поднимает туннели Mini App и Garage и пишет их адреса в `.env` (включая `TMA_STORAGE_ORIGINS`).
2. Открыть страницу спайка кнопкой меню бота: `make cli ARGS="set-menu-button https://<туннель Mini App>/__spike/upload"`. В Telegram маршрут живёт в hash, поэтому dev-сборка сама переводит путь `/__spike/upload` на этот экран (`apps/tma/src/main.tsx`). Вернуть обычную кнопку — `make tunnel` или `make cli ARGS=set-menu-button`.
3. Сценарии: «Галерея» — 3 фото разом, включая HEIC; «Камера» — снимок; видео больше 50 MB; во время загрузки видео включить авиарежим, выключить и нажать «Повторить».
4. «Копировать лог» → прислать лог. В нём клиент Telegram, User-Agent, `type` и размер каждого файла, попытки, время и результат HEAD. Результаты вносятся в таблицу выше.

## Заметки

- Без `make dev` в `backend/.env` остаётся адрес старого туннеля в `S3_PUBLIC_ENDPOINT_URL`, и ссылки ведут в никуда. Пустая переменная окружения его не перекрывает: настройки игнорируют пустые значения. Для локального прогона без туннеля нужно явно задать `S3_PUBLIC_ENDPOINT_URL=http://127.0.0.1:59100` и `TMA_STORAGE_ORIGINS=http://127.0.0.1:59100`.
- В обычном Chrome SDK не видит Telegram, и страница не входит сама. Для локальной проверки сессию выставляли вручную через модуль `api-client` на dev-сервере.
- Эндпоинты `/__spike` и страница удаляются в 2.1. Порт `StoragePort` и адаптер остаются.
