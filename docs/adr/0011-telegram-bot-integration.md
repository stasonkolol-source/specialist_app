# ADR-0011: Интеграция с Telegram — один бот с Main Mini App, aiogram, webhook, отдельный процесс

- **Статус:** принято
- **Дополнено** [ADR-0019](0019-goods-section-module-deferred.md) (раздел «Вещи», после MVP, итерация «Вещи»): зарезервированы типы deep links `g_`, `gh`, `gs_`, `gu_`, `gc_`; для фото объявлений бот — основной канал загрузки.
- **Дата:** 2026-09-26
- **Связанные документы:** [research/02-telegram-platform.md](../research/02-telegram-platform.md), [research/03-backend-stack.md §10.1](../research/03-backend-stack.md#101-как-бот-встраивается-в-модульный-монолит), [ADR-0009](0009-authentication-and-identity.md), [ADR-0010](0010-messaging-hybrid-chat.md)

## Контекст

На этапе 1 Telegram — единственный канал продукта. Через него идут:
- запуск Mini App;
- авторизация;
- уведомления (push-уведомлений у Mini App нет);
- шаринг и вирусность;
- приём Stars (v1).

**Ограничения платформы:**
- бот не пишет первым: нужен `/start` или явное согласие (`requestWriteAccess`);
- лимиты рассылки: около 1 msg/s на чат и около 30 msg/s глобально; paid broadcasts доступны только от 100 000 MAU и 100 000 Stars на балансе;
- с Bot API 10.2 (с 2026-07-20) методы Mini App (`Telegram.WebApp.*`) работают только на исходном origin приложения.

Бизнес-логика должна жить в backend (API-first), бот — лишь ещё один интерфейс.

## Рассмотренные варианты

| Вопрос | Варианты | Выбор и почему |
|---|---|---|
| Библиотека бота | aiogram 3.31 (Bot API 10.3, релизы через 0–3 дня после Telegram, async, FSM в Valkey). python-telegram-bot 22.8 (отстаёт на три версии Bot API). pyTelegramBotAPI 4.37 (проще, но слабее архитектура) | **aiogram**: быстрее всех поддерживает новые методы Bot API, одна async-модель с FastAPI и воркерами |
| Приём апдейтов | Webhook в отдельном процессе `bot`. Webhook-роут внутри `web` (`feed_webhook_update`). Long polling (пока установлен webhook, `getUpdates` недоступен) | **Отдельный процесс `bot`**: изоляция и независимые рестарты; всплески апдейтов не влияют на API. Переключение на роут внутри `web` — смена entrypoint. Polling — только в dev |
| Точка входа Mini App | Main Mini App (кнопка в профиле бота, вкладка Apps, медиа-превью, ссылки `t.me/<bot>?startapp=`). Direct link `t.me/<bot>/<app>` (чекбокс write access при первом запуске). Только menu button | **Main Mini App**: он даёт дистрибуцию (кнопка в профиле, вкладка Apps, превью). Direct link не нужен — разрешение писать получаем через `requestWriteAccess` и `/start` |

## Решение

**Структура в Telegram**
- **Один бот** на окружение (prod, stage, dev — разные боты) с настроенным **Main Mini App**. Он даёт кнопку в профиле бота, вкладку Apps и медиа-превью на ru/sr/en.
- **Menu button** ведёт на тот же SPA.
- В каналах и группах кнопки `web_app` недоступны, поэтому там используем `url`-кнопки со ссылкой `t.me/<bot>?startapp=…`.

**Схема deep links** — фиксируется до первого шаринга, потому что ссылки годами живут в чатах:
- Формат `startapp`: `<тип>[_<id>][_r<code>]`, не длиннее **64 символов** из алфавита `[A-Za-z0-9_-]`. Префикс `_tgr_` не используем: он зарезервирован Telegram под партнёрские ссылки.
- Типы:

  | Тип | Куда ведёт |
  |---|---|
  | `j_<id>` | Заявка |
  | `s_<id>` | Специалист |
  | `c_<id>` | Диалог |
  | `d_<id>` | Сделка |
  | `h` | Главная |

- `<id>` — base62 от UUID, **22 символа**.
- Суффикс `_r<code>` — реферал или атрибуция канала, например `s_<id>_rAB12CD` или `h_rAB12CD`. Буква `r` используется **только как суффикс**, типа `r` нет.
- Команды боту: `start=<param>`, например `start=link_<nonce>` — привязка аккаунта (этап 2). Других префиксов (`job_`, `spec_`, `ref_`, `login_`) нет.
- Значение `start_param` используется для роутинга сразу, а доверяется ему только после проверки подписи `initData`.

**Фронтенд на одном origin**
- Весь SPA живёт на одном домене `app.<domain>`. Этого требует защита Bot API 10.2: методы `Telegram.WebApp.*` работают только на исходном origin приложения.
- API проксируется на тот же origin (`app.<domain>/api`), чтобы не было CORS и preflight-запросов. На обычные API-запросы правило 10.2 не распространяется, здесь выигрыш — только в отсутствии CORS.
- Внешние страницы (оплата картой, OAuth) не вызывают `Telegram.WebApp.*`.

**Библиотека и процесс**
- **aiogram 3.31.x** (Bot API 10.3). Выбран за скорость поддержки новых Bot API (релиз через 0–3 дня), async и FSM в Valkey.
- **Webhook** с `secret_token` и узким `allowed_updates`: `message`, `callback_query`, `my_chat_member`, `pre_checkout_query`, `inline_query`, `chosen_inline_result`.
- **Отдельный процесс `bot`** из того же Docker-образа: aiohttp-обработчик aiogram. Хендлеры — тонкие адаптеры: разбирают ввод, вызывают application services **in-process** (без HTTP к собственному API), рендерят ответ (i18n, клавиатуры, deep links). Переключение на вариант «webhook-роут внутри `web`» — это смена entrypoint.
- **FSM** в Valkey с TTL. Длинные черновики (например, заявка) хранятся в PostgreSQL как `draft`.

**Исходящие сообщения**
- Отправляет воркер (очередь `notifications`), а не процесс бота; используется объект `Bot` aiogram как HTTP-клиент.
- Лимитер — token bucket в Valkey: **25 msg/s глобально, 1 msg/s на чат**.
- Приоритеты:

  | Приоритет | Что входит |
  |---|---|
  | P0 | Сообщения чата, выбор исполнителя, `deal.proposed`, открытые споры, ограничения аккаунта |
  | P1 | Новые отклики, напоминания о сделке, приглашения в заявку, отмена сделки |
  | P2 | Новые заявки по подпискам |
  | P3 | Дайджесты, истечение заявок, системные напоминания |

- Обработка ответов Bot API: 429 → пауза на `retry_after`; 403 → канал `disabled` и событие `my_chat_member`; 400 не ретраим.
- Тихие часы 22:00–08:00 Europe/Belgrade (настраиваются в `notifications.user_settings`) действуют для всего, кроме сообщений чата, выбора исполнителя, `deal.proposed` и заявок со срочностью `asap`.
- **Разрешение писать** запрашиваем контекстно: после публикации заявки («Сообщать об откликах?») и при создании подписки на заявки. Разрешение дают `requestWriteAccess` из Main Mini App и `/start` в боте; состояние видно по `allows_write_to_pm`. Чекбокс write access при первом запуске есть только у direct-link Mini App, мы их не используем.

**Сервисные функции**
- Локализованные имя, описание и команды бота (`setMyName` / `setMyDescription` / `setMyCommands` с `language_code`).
- Своя privacy policy в BotFather. Команды `/terms`, `/help`, а с появлением Stars — `/paysupport`.

**Шаринг**
- **MVP:** `savePreparedInlineMessage` + `WebApp.shareMessage` (карточка с фото и кнопкой); запасной путь — `t.me/share/url`.
- **v1:**
  - inline mode (`@bot электрик лиман`);
  - guest mode (Bot API 10.0) для комьюнити-чатов;
  - веб-страницы карточек с Open Graph для Viber и WhatsApp;
  - автопостинг заявок в городские каналы.

**Не делаем в MVP**
- Business-ботов;
- топики в личных чатах (комиссия 15% на Stars, [ADR-0010](0010-messaging-hybrid-chat.md));
- Local Bot API Server: медиа загружаются в S3 напрямую, бот принимает фото только как запасной путь (до 20 MB);
- paid broadcasts (доступны только от 100 000 MAU и 100 000 Stars на балансе).

## Последствия

**Положительные**

- Весь бизнес живёт в application services: бот, Mini App и будущий iOS-клиент используют одну логику.
- Рассылки изолированы от приёма апдейтов: всплеск уведомлений не тормозит ответы бота.
- Схема deep links единая для бота, каналов, шаринга и будущих universal links iOS.

**Отрицательные и риски**

| Риск | Смягчение |
|---|---|
| Одностороннее изменение правил Telegram: пороги paid broadcasts, комиссии, ToS | Telegram — один из клиентов; ядро продукта от механик Telegram не зависит |
| Лимит 30 msg/s: рассылка на 10 000 подписчиков занимает около 6 минут | Дайджесты, умные подписки (точные категории и районы), приоритеты. На этапе 2 — push |
| Пользователь не разрешил боту писать | Центр уведомлений в Mini App; повторная просьба в контексте; метрика «доля пользователей с включёнными уведомлениями» |

**Что сделать**

- Тестовое окружение Telegram (test server) и отдельные боты для каждого окружения.
- Матрица ручного тестирования клиентов: iOS, Android (включая слабое устройство), Desktop, Web A/K.
- Конструктор deep links и обратный парсер — в `growth` с юнит-тестами на лимит 64 символа.
