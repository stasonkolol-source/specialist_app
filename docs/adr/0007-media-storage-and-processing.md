# ADR-0007: Медиа — Cloudflare R2 (EU), загрузка по presigned URL, обработка в воркере, CDN

- **Статус:** принято
- **Дополнено** [ADR-0019](0019-goods-section-module-deferred.md) (раздел «Вещи», после MVP, итерация «Вещи»): `purpose='listing'`, vision-проверка всех фото, сроки хранения задачами приложения, сброс кэша CDN при снятии.
- **Дата:** 2026-09-26
- **Связанные документы:** [research/03-backend-stack.md §6](../research/03-backend-stack.md#6-медиа-хранение-и-обработка), [research/07-postgres-lab-and-infra.md §4.1](../research/07-postgres-lab-and-infra.md#41-локальный-docker-compose-для-разработки-b1), [research/02-telegram-platform.md §7](../research/02-telegram-platform.md#7-медиа), [ARCHITECTURE.md §10](../ARCHITECTURE.md#10-медиа-пайплайн)

## Контекст

Какие медиа есть в продукте:
- аватары;
- портфолио специалистов (фото и короткие видео);
- фото к заявкам;
- в v1 — фото в чате и к отзывам;
- документы для ручной верификации (APR, лицензии).

Ограничения:
- **Лимиты Bot API** (скачивание ботом до 20 MB) не годятся для портфолио-видео.
- **WebView Telegram:** `<input type=file>` ведёт себя по-разному на клиентах; с iPhone приходят HEIC-фото и HEVC-видео.
- **Приватность:** EXIF с GPS раскрывает адрес клиента, фото третьих лиц — это персональные данные.
- **Трафик:** медиа — основной исходящий трафик. Платный egress (AWS — $0,09/GB) заметно ударит по бюджету.
- **Локальная разработка:** MinIO больше не распространяется — репозиторий заархивирован 2026-04-25, образы удалены с Docker Hub 2026-09-11.

## Рассмотренные варианты

| Хранилище | Хранение | Egress | Минусы |
|---|---|---|---|
| **Cloudflare R2** (EU jurisdiction) | $0,015/GB-мес | Бесплатно | Нет presigned POST с `content-length-range` → обязательна проверка после загрузки |
| Hetzner Object Storage | €6,49 за 1 TB хранения + 1 TB egress | Сверх — ≈€1/TB **[Допущение: вторичный источник]** | Нет custom domains, лимит 750 req/s на бакет |
| Backblaze B2 | $6,95/TB | Бесплатно до 3× объёма | Нет presigned POST |
| AWS S3 | $0,0245/GB | $0,09/GB | Дорогой egress |

| Обработка | Оценка |
|---|---|
| Варианты заранее в воркере (Pillow + pillow-heif) | Просто, без отдельного сервиса |
| imgproxy на лету за CDN | Гибко для разных DPI мобильных клиентов, но ещё один сервис |
| ffmpeg в воркере | Бесплатно, полный контроль |
| Managed-видео (Mux, Bunny Stream, Cloudflare Stream) | Дешевле собственного труда, если видео станет центральной фичей |

## Решение

1. **Хранилище — Cloudflare R2 с EU jurisdiction**, три бакета:

   | Бакет | Что хранит | Доступ |
   |---|---|---|
   | `incoming` | Сырые загрузки | Приватный; lifecycle удаляет объекты старше 2 дней и незавершённые multipart |
   | `media` | Обработанные варианты | Публичный через custom domain `cdn.<domain>` с Cloudflare Cache (правило Cache Everything) |
   | `private` | Оригиналы, вложения чата, документы верификации | Выдача только короткоживущими presigned GET |

   PoP Cloudflare есть в Белграде. Бэкапы БД лежат отдельно — в Hetzner Object Storage и втором провайдере ([ADR-0015](0015-hosting-and-deployment.md)).
2. **Загрузка напрямую с клиента** (Mini App, позже мобильное приложение), минуя backend:
   1. `POST /media/uploads` → сервер проверяет квоты, allow-list MIME и размер → запись `media.assets(status=pending_upload)` → **presigned PUT** на 10 мин с подписанными `Content-Type` и ключом. Для видео больше 50 MB — multipart с presigned URL на каждую часть, в CORS бакета выставлен `ExposeHeaders: ETag`.
   2. Клиент загружает файл в R2: фото предварительно сжимает до ≈2048 px, видео не сжимает.
   3. `POST /media/uploads/{id}/complete` → `HEAD`-проверка размера и типа → в той же транзакции статус `uploaded` и задача `media.process`.
   4. Для boto3 с не-AWS endpoint нужен `request_checksum_calculation="when_required"`.
3. **Обработка — воркер `worker-media`** (отдельный процесс с лимитами CPU и памяти):
   - тип файла определяется по magic bytes, а не по заголовку клиента;
   - **изображения** (Pillow + pillow-heif):
     - нормализация ориентации, **обязательное удаление EXIF и GPS** на сервере, даже если клиент уже удалил;
     - WebP-варианты 320, 800 и 1600 px;
     - thumbhash-плейсхолдер;
     - pHash для поиска дубликатов между аккаунтами (антифрод, [ADR-0016](0016-trust-safety-and-reviews.md));
   - **видео** (ffmpeg в `asyncio.create_subprocess_exec` с таймаутом):
     - `ffprobe`-лимиты: MVP ≤ 60 с и ≤ 200 MB исходника;
     - перекодирование в H.264 (yuv420p) + AAC, MP4 720p с `-movflags +faststart`;
     - постер в WebP;
     - кадры раз в 2–3 с — на модерацию;
   - **модерация:** OpenAI `omni-moderation` (бесплатно), при срабатывании — SafeSearch или Rekognition, затем `moderation_status`. Портфолио новых профилей проходит ручную проверку в очереди P2.
4. **Раздача.** Публичные варианты отдаются через `cdn.<domain>` с долгим кэшем (ключи неизменяемые, в ключе — id варианта). Видео — MP4 с range-запросами, в WebView с `playsinline muted preload="metadata"`.
5. **Лимиты MVP** (гипотезы, [открытый вопрос](../ARCHITECTURE.md#19-риски-и-открытые-вопросы)):

   | Что | Лимит |
   |---|---|
   | Фото | ≤ 15 MB исходник (портфолио, заявки); ≤ 10 MB (аватар, сообщения, отзывы) |
   | Портфолио | до 60 фото и 6 видео |
   | Заявка | до 6 фото |
   | Аватар | 1 |

6. **Ретеншн:**
   - `incoming` — 2 дня;
   - удалённые пользователем медиа — физически через 30 дней;
   - отклонённые модерацией — 6 месяцев (окно апелляции), затем удаление;
   - документы верификации (v1) — через 30 дней после решения **[Допущение]**;
   - legal hold: медиа из открытых `moderation.cases` и `deals.disputes` не удаляются до закрытия кейса.
7. **Локальная разработка — Garage v2.4.1** (S3-совместимый, 4 MiB RAM; на arm64 проверены presigned PUT, GET и POST и CORS). Запасные варианты — RustFS 1.0 и SeaweedFS 4.47. Особенность Garage: на просроченную ссылку он отвечает 400, а не 403, клиент обрабатывает оба кода.
8. **Позже:**
   - **imgproxy 4.x за CDN** (проверен с Garage) — когда мобильным клиентам понадобятся произвольные размеры;
   - **Mux или Bunny Stream** — если видео станет ключевой фичей или ffmpeg начнёт мешать бюджету CPU.

## Последствия

**Положительные**

- Трафик медиа не идёт через backend и почти ничего не стоит, потому что egress R2 бесплатный.
- Один и тот же контракт загрузки для Mini App, iOS и Android.
- Приватность обеспечена по умолчанию: EXIF удаляется на сервере, у приватных объектов нет публичных URL.

**Отрицательные и риски**

| Риск | Смягчение |
|---|---|
| Нет presigned POST с ограничением размера | `HEAD`-проверка после загрузки, lifecycle для мусора, квоты на пользователя |
| Условия Cloudflare о раздаче видео не на Enterprise-плане. Считаем, что R2 с custom domain относится к Developer Platform и разрешён, — это допущение | При сомнениях — видео через Bunny Stream или Mux |
| Транскодирование нагружает CPU | Отдельный процесс и очередь `media`, лимиты длительности, при росте — отдельная VM |
| Лицензия AGPL у Garage | Используется только локально и в CI, в продакшене не применяется |

**Что сделать**

- Спайк загрузки из WebView Telegram на iOS и Android: HEIC, большие видео, несколько файлов, прогресс и повторы.
- Интеграционный тест R2 на stage: presigned PUT, multipart, `HEAD`-проверка, checksum `when_required`.
- Lifecycle-правила и CORS для бакетов (`incoming`, `media`, `private`) — в Terraform.
- Worker-media с лимитами CPU и памяти и тестами на EXIF, GPS и decompression bomb.
