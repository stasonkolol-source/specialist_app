# ADR-0021: Уточнения реализации платформы (этап 0)

- **Статус:** принято
- **Дата:** 2026-09-27
- **Связанные документы:** [ADR-0020](0020-code-patterns-and-consistency.md), [ADR-0008](0008-background-jobs-and-outbox.md), [ADR-0009](0009-authentication-and-identity.md), [ADR-0003](0003-api-first-rest-openapi.md), [docs/spikes/0.6](../spikes/0.6-sqla-geoalchemy.md), [docs/spikes/0.8](../spikes/0.8-procrastinate-tx.md), [docs/spikes/0.14](../spikes/0.14-initdata-jwt.md), [DEVELOPMENT_PLAN.md](../DEVELOPMENT_PLAN.md) шаги 0.5–0.23, 1.1–1.3a

## Контекст

ADR-0020 задал паттерны кода. При реализации этапа 0 спайки, контрактные тесты (schemathesis) и ревью нашли места, где «очевидная» реализация ломается. Уточнения живут в коде и записках спайков. Этот ADR собирает их в одно место: правила, которые не видны из кода с первого взгляда, но которые нельзя нарушать.

## Решение

### 1. Транзакции и очередь (ADR-0008, ADR-0020 §4)

- **Savepoint для постановки задачи — на уровне psycopg** (`driver.transaction()`), а не `session.begin_nested()`. SQLAlchemy шлёт `SAVEPOINT` лениво, и вставка Procrastinate мимо SQLAlchemy шла бы без него. `AlreadyEnqueued` считается успехом.
- **Перед COMMIT UoW проверяет `INERROR`.** PostgreSQL отвечает на `COMMIT` в упавшей транзакции командой `ROLLBACK`, а SQLAlchemy не бросает исключения. Поэтому UoW бросает `FailedTransactionError`, а не молча теряет данные и задачи.
- **На пуловых соединениях — только `SET LOCAL`.** Сессионный `SET search_path` протёк через пул роли migrator и сломал соседний тест.
- **Своя транзакция чтения закрывается сразу:** вне UoW `SqlQuery` откатывает autobegin. UoW при входе откатывает транзакцию, в которой были только чтения; если в ней есть записи, бросает `WriteOutsideUnitOfWorkError`. Одиночное чтение вне UoW идёт на соединении в `AUTOCOMMIT` (перф-аудит 2026-10): без BEGIN и ROLLBACK на проводе — два обмена с базой вместо четырёх; уровень изоляции пул возвращает при возврате соединения. `pool_pre_ping` остаётся: проверка — один короткий обмен, а без неё первый запрос после рестарта PostgreSQL падал бы 500.

### 2. Репозитории и ORM

- **`check_loaded_version` в `save`.** Identity map держит объекты по слабым ссылкам, и `session.get` может перечитать уже более новую версию строки. Тогда проверка `version_id_col` проходит, хотя агрегат устарел. Версию сверяет репозиторий, генератора версии в ORM нет.
- **Вложенные сущности агрегата сравниваются по значению** (`AuthIdentity` — `@dataclass` с `eq=True`): снимок UoW для проверки забытого `save` делается через `deepcopy`.
- **GeoAlchemy — `spatial_index=False`** и явный GiST в `__table_args__`: иначе GeoAlchemy создаёт второй индекс.
- **Справочники** (`geo`, `catalog`) — `int GENERATED ALWAYS AS IDENTITY`. Идемпотентный импорт сидов: `seed_hash` исходных данных, неизменённая строка не трогается, повторный `cli seed` ничего не меняет.

### 3. Миграции

- **Autogenerate дублирует CHECK** для `Enum(create_constraint=True)`: в миграции колонка — `String(N)` и один CHECK с именем по конвенции. Свои типы приложения (`LocalizedTextType`, `GeoPointType`) в миграции заменяются на `JSONB` и типы GeoAlchemy.
- **MetaData модулей для Alembic собирает `app/entrypoints/_metadata.py`**: `platform` модулей не видит (import-linter).
- **Одна head всегда.** Параллельные шаги с миграциями перед слиянием ставят `down_revision` на текущую head main (тест раунд-трипа это проверяет).

### 4. HTTP и контракт (ADR-0003)

- **401 раньше 422.** Проверка входа — зависимость маршрута `AUTHENTICATED`, она выполняется до разбора тела и параметров. `Principal` строится лениво в провайдере и кэшируется в REQUEST scope.
- **Целочисленные id в пути ограничены int4** (`Path(ge=1, le=2**31-1)`): иначе огромный id даёт ошибку БД и 500.
- **`Allow` у 405 берётся из схемы OpenAPI.** Starlette перечисляет только методы первого совпавшего маршрута.
- **Ошибки — ответ `default` с `application/problem+json` (ProblemOut)** в схеме. `info.version` — версия контракта, а не релиз: схема не меняется от деплоя. `backend/openapi.json` в git, CI сверяет его с кодом, api-client перегенерируется из него же.
- **`detail` ошибок локализован** (`errors.<code>` в каталогах gettext); архитектурный тест требует ключ для каждого кода ошибки.
- **Идемпотентность — собственный класс маршрута** (`IdempotentRoute`): ему видны и тело запроса, и ответ. Зависимость FastAPI с `yield` ответа не видит.
- **Контрактные тесты (schemathesis) — часть `make check`** против живого uvicorn в потоке. Они уже нашли три дефекта: `Allow`, 401/422 и int4.

### 5. Вход и сессии (ADR-0009)

- **Refresh-токен `<sid>.<secret>`.** Ротация идёт в той же строке сессии: хранятся хэш текущего и предыдущего секрета. Повтор предыдущего в течение 10 с — ответ 401 без отзыва сессии, повтор более старого — отзыв сессии целиком. Обновление идёт под `SELECT … FOR UPDATE`.
- **Бот и Mini App регистрируют пользователя одним кодом** (`sign_in_telegram`). Бот узнаёт пользователя по `from.id` через фасад identity. Telegram id в логи не пишется, только внутренний `user_id`.

### 6. Отказоустойчивость вспомогательных хранилищ

Лимиты запросов, denylist сессий и кэш client-config при недоступном Valkey или БД **пропускают запрос (fail open)** и пишут предупреждение в лог. Антиспам и конфигурация не должны ронять API. Отзыв сессии тогда запаздывает не больше чем на время жизни access-токена (15 минут).

### 7. Процессы и сборка

- **Роутеры бота модулей — фабрика `create_router()`:** роутер aiogram подключается только к одному диспетчеру.
- **Образ backend не устанавливает пакет:** код лежит в `/app/src`, а пути к `locales/`, `seeds/` и `migrations/` считаются от исходников. Роль процесса — аргумент точки входа.
- **Тесты модулей не импортируют `app.entrypoints` и `app.interfaces`** (import-linter). Общие фикстуры (настройки, HTTP-клиент, сиды) лежат в `backend/tests/plugins`.

## Последствия

- Новые модули повторяют эти правила через шаблон copier и эталонные модули `identity` и `geo`. Нарушения ловят архитектурные тесты, import-linter и контрактные тесты.
- Если правило из этого ADR нужно нарушить, это оформляется так же, как исключение из ADR-0020: комментарий `# ADR-0021: исключение — <причина>`.
