# ADR-0013: Мультиязычность — ru, sr (Cyrl/Latn), en; справочники в JSONB, UGC в оригинале

- **Статус:** принято
- **Дата:** 2026-09-26
- **Связанные документы:** [ARCHITECTURE.md §7.4](../ARCHITECTURE.md#74-мультиязычный-контент), [ADR-0006](0006-search-in-postgresql.md), [research/07-postgres-lab-and-infra.md](../research/07-postgres-lab-and-infra.md), [research/03-backend-stack.md §9.3](../research/03-backend-stack.md#93-i18n)

## Контекст

- **Языки аудитории.** Основная аудитория говорит по-русски, вторичная — по-сербски. Сербский существует в двух письменностях: кириллица официальна, латиница доминирует в интернете и в быту. Английский нужен для международной аудитории и как нейтральный fallback.
- **Три вида контента:**
  - строки интерфейса и уведомлений;
  - справочники (категории, районы, продукты);
  - пользовательский контент (профили, заявки, отзывы, сообщения).
- **Особенность сербского.** Транслитерация кириллица → латиница однозначна (буква в букву: Љ→Lj, Њ→Nj, Џ→Dž). Обратная неоднозначна: в «injekcija» `nj` — это две буквы, а не Њ.
- **Требование к поиску.** Искать нужно поперёк языков: клиент пишет «электрик», профиль заполнен как «električar».

## Рассмотренные варианты

- **Справочники.** Колонки на каждый язык (`name_ru`, `name_sr`…) / JSONB с ключами локалей / отдельные таблицы переводов.
- **UGC.** Хранить только оригинал / хранить оригинал и обязательный перевод / хранить оригинал и переводить по запросу с кэшем.
- **Источник сербских строк.** Латиница с генерацией кириллицы / кириллица с генерацией латиницы.

## Решение

1. **Локали интерфейса** (BCP 47): в MVP — `ru`, `sr-Latn`, `sr-Cyrl` (исходник сербского — кириллица, латиница генерируется); `en` — v1.
   - Порядок выбора: настройка пользователя → `language_code` Telegram (`sr` → `sr-Latn`) → `Accept-Language` → `ru`.
   - Сербский по умолчанию — латиница; кириллица включается в настройках.
2. **Строки интерфейса:**
   - Фронтенд — ICU MessageFormat, библиотека по [ADR-0012](0012-mini-app-frontend-and-mobile-path.md).
   - Backend (ошибки API, сообщения бота, push) — gettext-каталоги через Babel, общие для API и бота. Числа, даты и RSD форматируются через Babel и CLDR.
   - **Исходник сербских строк — кириллица** (`sr_Cyrl`). `sr_Latn` генерируется автоматически и вычитывается. Для русского и английского исходники ведутся вручную.
3. **Справочники** — JSONB `{"ru": …, "sr-Cyrl": …, "sr-Latn": …, "en": …}` в той же строке:
   - `sr-Latn` генерируется из `sr-Cyrl` при сохранении, если не задан вручную;
   - API отдаёт одну строку на языке запроса;
   - fallback: `sr-Cyrl` → `sr-Latn` → `en` → `ru`; `sr-Latn` → транслит(`sr-Cyrl`) → `en` → `ru`; `ru` → `en` → `sr-Latn`; `en` → `ru` → `sr-Latn`;
   - сортировка — ICU-коллации.
4. **Пользовательский контент** хранится в оригинале вместе с `content_lang`:
   - язык определяется автоматически, пользователь может его поправить;
   - сербский текст, написанный кириллицей, при запросе `sr-Latn` отдаётся в латинице (конверсия на лету, однозначная);
   - латинский текст в кириллицу автоматически не конвертируем — показываем как есть.
5. **Машинный перевод UGC (v1)** — по кнопке «Показать перевод» (профили, заявки, отзывы, сообщения):
   - кэш в `platform.translations` по хэшу исходника;
   - провайдер — LLM или DeepL за портом `Translator`;
   - обязательного перевода при публикации нет: это дорого и искажает смысл.
6. **Поиск поперёк языков** ([ADR-0006](0006-search-in-postgresql.md)):
   - словарь `catalog.search_terms` («электрик», «električar», «електричар», «electrician» → одна категория);
   - индексирование названий категорий на всех языках в документ поиска;
   - сербский текст перед FTS проходит `sr_cyr2lat()` и замену `đ` → `dj`, затем конфигурацию `sr_unaccent` (unaccent + `serbian_stem`); для pg_trgm используется ключ `search_norm` (нижний регистр, транслит в латиницу, без диакритики).
7. **Бот:** имя, описание, команды и тексты локализуются по `language_code` через тот же каталог Babel.

## Последствия

**Положительные**

- Новый язык (например, украинский) добавляется новым ключом JSONB и новым каталогом, без миграций схемы.
- Одна строка на справочник, кэшируется целиком.
- Нет искажений автоматической транслитерации «латиница → кириллица».

**Отрицательные и риски**

| Риск | Смягчение |
|---|---|
| Контент-менеджеру удобнее писать сербские тексты латиницей | В админке поле `sr-Cyrl` можно заполнить автоконвертацией из латиницы с обязательной вычиткой |
| Качество автоопределения языка на коротких текстах | Пользователь может поправить; для поиска это некритично, потому что индексируется в нескольких конфигурациях |
| Стоимость машинного перевода | Перевод только по запросу, кэш, лимиты на пользователя |

**Что сделать**

- Утилита транслитерации `sr-Cyrl → sr-Latn` с тестами (включая заглавные диграфы: «ЉУБАВ» → «LJUBAV», «Љубав» → «Ljubav»).
- Проверка в CI: у справочника обязательно заполнены `ru` и `sr-Cyrl`.
- Глоссарий терминов продукта на трёх языках («заявка», «отклик», «сделка») — для единообразия интерфейса и бота.
