# 04. Фронтенд Telegram Mini App и путь в App Store / Google Play

**Дата:** 2026-09-26
**Фокус:** стек Mini App, особенности Telegram WebView, UX, переход к нативному приложению, требования App Store и Google Play, что заложить в API уже сейчас.
**Методология.** Версии пакетов проверены командой `npm view <pkg> dist-tags time` в registry.npmjs.org 2026-09-26 [23]. Покрытие Bot API в SDK проверено grep-ом по опубликованным tarball-ам пакетов. Правила сторов прочитаны напрямую на официальных страницах: App Review Guidelines в редакции «Last Updated: June 8, 2026» [51] и Play Console Help. UX опирается на официальные гайдлайны Telegram [1] и локальную базу ui-ux-pro-max [37], это не веб-источник. В ходе сессии закончился лимит веб-поиска, поэтому часть утверждений (примеры крупных брендов, поведение отдельных WebView) подтвердить не удалось; они помечены **[Допущение]**.

---

## TL;DR

1. **Стек Mini App:** React 19.x (сейчас 19.3; после подключения Expo — та версия, которую пинит SDK) + TypeScript 6.0 + Vite 8.3 + `@tma.js/sdk-react` 3.0 + TanStack Router/Query + React Hook Form + Zod 4 + i18next + API-клиент, сгенерированный orval из OpenAPI. UI строим на собственных компонентах поверх CSS-переменных темы Telegram (Tailwind 4). TelegramUI допустим только как ускоритель MVP, за своими обёртками.
2. **Почему React:** только он даёт реальное переиспользование кода с React Native (хуки, TanStack Query, RHF, Zod, i18next, типы). У Vue и Svelte хорошие TMA SDK, но путь в стор у них только через Capacitor.
3. **SDK:** `@telegram-apps/*` фактически заменён на `@tma.js/*`: vue/svelte/solid/bridge-пакеты помечены deprecated [23]. `@tma.js/sdk` 3.3.0 покрывает Bot API до 9.5, но `requestChat` (9.6) в нём нет. `@twa-dev/sdk` остановился на 8.0 (последний релиз 2025-02-05).
4. **Платформа Telegram:** актуальна Bot API 10.3 (2026-08-24). С 2026-07-20 методы Mini App работают только с исходного origin (Bot API 10.2) [2], поэтому приложение держим на одном домене.
5. **Идентичность:** «Log In with Telegram» теперь работает по стандартному OpenID Connect (Authorization Code + PKCE) [3]. В апреле 2026 объявлена поддержка нативных SDK для iOS и Android [4][5]. Через Telegram Gateway коды OTP стоят $0.01 [9]. Этого хватает, чтобы связать аккаунт из Mini App (initData) с нативным приложением.
6. **Цифровая монетизация** (PRO-подписка специалиста, продвижение, платные отклики):
   - в Telegram оплата цифровых товаров идёт только в Stars (XTR) [6][7];
   - в iOS нужен IAP (3.1.1, «boosts» по 3.1.3(g));
   - в Android нужен Play Billing [74].
   - Оплату физической услуги мастеру **нельзя** проводить через IAP или Play Billing (3.1.3(e) [51], Payments policy [74]).
7. **Сербия:** на неё не распространяются исключения для США (Epic) и ЕС (DMA) [56][64]. Новые комиссии Google для «Rest of World» вступят в силу только 2027-09-30 [80]. До тех пор ставка 15% на первый $1M и 15% на подписки [81]; у Apple 15% в Small Business Program [69].
8. **Обязательно для App Store:**
   - UGC по 1.2: фильтрация, жалобы, блокировка, контакты;
   - удаление аккаунта в приложении, включая UGC и отзывы [65];
   - каталог доступен без логина (5.1.1(v));
   - демо-аккаунт для ревью (2.1);
   - приложение работает **без установленного Telegram** (4.2.3(i));
   - если в iOS есть вход через Telegram, нужна эквивалентная опция вроде Sign in with Apple (4.8);
   - новая анкета возрастного рейтинга: ответы про social media обязательны с сентября 2026 [58].
9. **Обязательно для Google Play:**
   - UGC policy: принятие ToS до публикации, report и block в приложении [72];
   - удаление аккаунта в приложении и по веб-ссылке [73];
   - Data safety, включая SDK [75];
   - системный Photo Picker [83];
   - target API 36 с 2026-08-31 [76];
   - organization-аккаунт, чтобы не проходить правило «12 тестеров × 14 дней» [77].
10. **Мобильный путь:** Expo + Expo Router + EAS. Сейчас стабильна SDK 57 (RN 0.86, React 19.2), SDK 58 в бете: RN 0.88 RC, собрана под iOS 27 [38][39]. Общие пакеты в pnpm + Turborepo монорепо: api-client, Zod, i18n, токены, доменная логика, headless-хуки. UI пишется заново.
11. **«Одна кодовая база» на RN Web / Expo web / Tamagui как Mini App технически реальна** (Bluesky так работает на web, iOS и Android [49]), но для 1–2 разработчиков на этапе 1 не рекомендую. Причины: +74.5 KB gz на `react-native-web` [24], потеря Telegram-нативного вида, сложнее чинить особенности WebView, а карты, медиа, auth и платежи всё равно разные.
12. **Альтернативы:**
    - Capacitor — самый быстрый путь, но с потолком UX и риском отказа по 4.2 [51][50];
    - Flutter — ноль переиспользования с React Mini App;
    - PWA — дополнение для местных пользователей без Telegram, но не путь в стор.
13. **Mini App проектируем как web-приложение с Telegram-адаптером.** Все платформенные вызовы идут через интерфейс `platform`: auth, BackButton/MainButton, storage, haptics, share, location. Тот же билд работает в обычном браузере (для сербов без Telegram, как страница удаления аккаунта, как fallback для deep links) и упрощает порт на Expo.
14. **API-контракт закладываем сейчас:**
    - identities и связывание аккаунтов, собственные токены;
    - реестр устройств и push-токенов, каналы уведомлений (Telegram-бот / push);
    - канонические HTTPS-ссылки ↔ `startapp` ↔ universal links;
    - cursor-пагинация, ETag, idempotency keys, машинные коды ошибок;
    - `/v1`, `min_supported_version` для forced update, серверные feature flags;
    - entitlements, не зависящие от канала оплаты (Stars / IAP / Play / web);
    - эндпоинты модерации;
    - presigned-загрузки с серверной обработкой медиа (удаление EXIF/GPS, HEIC).
15. **Главные риски:**
    - SDK и UI-киты TMA держатся на одиночных мейнтейнерах;
    - трактовка платных откликов и бустов на ревью;
    - местная аудитория без Telegram **[Допущение]**;
    - вывод средств за Stars через Fragment;
    - TypeScript 7 пока несовместим с частью тулинга.

Рекомендация:
- Берём `@tma.js/sdk-react` и оборачиваем его в собственный пакет `platform`. Экраны не должны импортировать SDK напрямую.
- Методы, которых ещё нет в SDK (например `requestChat`), вызываем через низкоуровневый bridge или ждём релиза. Одновременно держать официальный скрипт и tma.js не стоит **[Допущение: возможны конфликты подписок на события]**.
- Для бэкенда (Python) initData проверяем сами:
  - HMAC-SHA-256 с ключом, выведенным из токена бота;
  - либо Ed25519-подпись `signature` с публичным ключом Telegram (для третьих сторон, с Bot API 8.0) [1].

## 2. Особенности WebView Telegram

### 2.1 Где исполняется Mini App

| Клиент | Движок | Что учесть |
|---|---|---|
| Telegram iOS | WKWebView, то есть WebKit версии iOS. Telegram iOS 12.9.4 (2026-09-12) требует iOS 13.0+ [13] | Vite 8 по умолчанию собирает под `ios16.4` [26]. Решить, поддерживаем ли iOS 13–16.3: понизить `build.target` или добавить legacy-плагин. **[Допущение]** доля таких устройств мала — проверить по аналитике |
| Telegram Android | Системный Android WebView (Chromium) | В User-Agent есть класс производительности LOW/AVERAGE/HIGH; на LOW упрощать анимации [1] |
| Telegram Desktop / macOS | Встроенный webview | Инспектор доступен только в Beta-версиях [1] |
| Telegram Web | Браузер, Mini App во iframe **[Допущение]** | Не запрещать фрейминг заголовками `X-Frame-Options`/`frame-ancestors`; не строить auth на cookies (third-party контекст) **[Допущение]** |

### 2.2 Производительность и бюджет бандла

Размеры тяжёлых зависимостей (bundlephobia, пакет целиком без tree-shaking, gzip) [24]:

|---|---|---|---|
| maplibre-gl 6.11.2 | 278.2 KB | leaflet 1.9.4 | 41.7 KB |
| zod 4.6.5 (полный) | 86.5 KB | valibot 1.5.0 | 14.4 KB |
| react-native-web 0.21.3 | 74.5 KB | @telegram-apps/telegram-ui 2.1.13 | 62.1 KB |

Практики:
- Бюджет первого экрана — до ~150–200 KB gz JS. Это рекомендация автора, не норматив **[Допущение]**.
- Code splitting по маршрутам. Карту, загрузчик медиа и редактор прайса грузим лениво.
- В BotFather настраиваем экран загрузки Mini App (иконка и цвета для светлой и тёмной темы) [1]: воспринимаемая скорость старта растёт бесплатно.
- Миниатюры (WebP/AVIF) генерируются на сервере, картинки отдаются через `srcset` и `loading="lazy"`, вместо спиннеров — skeleton.
- Анимации держим на 60 fps и отключаем на слабых Android по классу производительности из User-Agent [1].

### 2.3 Кэширование и хранение

- Хэшированные ассеты отдаём с `Cache-Control: public, max-age=31536000, immutable`, `index.html` — с `no-cache`. При несовпадении версии билда (ответ `/v1/app-config`) делаем мягкую перезагрузку.
- На Service Worker внутри Telegram iOS не полагаемся **[Допущение: в WKWebView сторонних приложений SW, как правило, недоступен]**. Офлайн для TMA не цель.
- Хранилища Telegram [1]:
  - **DeviceStorage** (Bot API 9.0): до 5 MB на пользователя, локально;
  - **SecureStorage** (9.0): iOS Keychain / Android Keystore, до 10 элементов;
  - **CloudStorage** (6.9): до 1024 ключей, значение до 4096 символов, синхронизируется между устройствами.
- Черновики заявок держим в DeviceStorage, настройки UI — в CloudStorage.
- Токены: при каждом запуске обмениваем initData на короткую сессию бэкенда и держим её в памяти. Refresh-токен в Mini App не нужен.

### 2.4 Темы: theme params → CSS variables

Telegram отдаёт CSS-переменные, которые меняются в реальном времени [1]:
- `--tg-theme-*`: bg, text, hint, link, button, button-text, secondary-bg, header-bg, bottom-bar-bg, accent-text, section-bg, section-header-text, section-separator, subtitle-text, destructive-text;
- `--tg-color-scheme`.

Как используем:
- Маппим их на семантические токены (`--color-surface`, `--color-primary` и т. д.). Компоненты используют только токены.
- Вне Telegram, в web-оболочке, подставляем свою палитру.
- Цвета хрома задаём методами `setHeaderColor`, `setBackgroundColor`, `setBottomBarColor`. Цвет нижней панели на Android применяется и к системной навигации [1].

### 2.5 Safe areas

- С Bot API 8.0 есть `safeAreaInset` / `contentSafeAreaInset` и CSS-переменные `--tg-safe-area-inset-*`, `--tg-content-safe-area-inset-*` [1].
- В fullscreen шапка прозрачная; Telegram всё равно рекомендует задавать `setHeaderColor` [1].
- Вне Telegram используем fallback на `env(safe-area-inset-*)`.

### 2.6 Клавиатура и viewport

- `viewportHeight` обновляется в реальном времени, но «should not be used to pin interface elements to the bottom». Для этого есть `viewportStableHeight` [1].
- `hideKeyboard()` доступен с Bot API 9.1 [2].
- Основное действие экрана («Далее», «Опубликовать», «Откликнуться») выносим в нативные **MainButton / SecondaryButton** (BottomButton, 7.10) [1]. Они не зависят от вёрстки и не прыгают при открытии клавиатуры.
- Для полей ввода задаём `inputmode="numeric"` (бюджет), `type="tel"`, `enterkeyhint`.

### 2.7 Навигация внутри Mini App

- Нативный **BackButton** (6.1) синхронизируем с историей роутера. Свою стрелку «назад» в шапке не рисуем.
- **SettingsButton** (7.0) открывает настройки.
- `enableClosingConfirmation` (6.2) включаем на несохранённых формах.
- `disableVerticalSwipes` (7.7) включаем только там, где жесты конфликтуют: карта, карусели. Документация советует держать свайпы включёнными [1].
- `start_param` передаётся через `?startapp=` и допускает только `A-Z a-z 0-9 _ -`, до 512 символов: `/^[\w-]{0,512}$/` [16].
- Launch params приходят в `location.hash`. Их нужно сохранить до инициализации роутера [17]; официальный шаблон использует `HashRouter` [18]. Для Telegram-оболочки берём memory/hash history, для web-оболочки — browser history.
- Main Mini App и direct links по умолчанию открываются на полную высоту; `mode=compact` открывает на половину [1].

### 2.8 Загрузка фото и видео

1. **Выбор файлов.** `<input type="file" accept="image/*" multiple>`. Поведение пикеров проверяем во всех клиентах: iOS, Android, Desktop, Web **[Допущение: встречаются различия]**.
2. **Сжатие фото на клиенте.** `createImageBitmap` + canvas/`OffscreenCanvas` (OffscreenCanvas есть с Safari/iOS 16.4 [30]), длинная сторона ~2048 px, JPEG/WebP с качеством около 0.8.
   - `compressorjs` 1.3.0 (2026-04-06) поддерживается.
   - `browser-image-compression` 2.0.2 (2023-03-06) и `heic2any` 0.0.4 (2023) давно без релизов [23].
3. **HEIC.** iOS обычно отдаёт JPEG при выборе через file input **[Допущение]**. Бэкенд всё равно принимает HEIC (pillow-heif) как страховку.
4. **Загрузка напрямую в S3.**
   - Фото — presigned PUT.
   - Видео — S3 multipart с presigned URL на каждую часть: часть 5 MiB–5 GiB, до 10 000 частей, у последней части нет минимума [33].
   - В CORS бакета выставляем `ETag` в `ExposeHeaders`, иначе браузер не прочитает ETag частей.
   - Готовый клиент с ретраями — Uppy 6 (`@uppy/aws-s3` 6.2.0, 2026-09-25) [23].
5. **Видео на клиенте не сжимаем** (ffmpeg.wasm слишком тяжёл для WebView **[Допущение]**). Вместо этого ограничиваем длительность и размер по метаданным и транскодируем на сервере.
6. **Сервер:** удаляет EXIF, в первую очередь GPS; генерирует превью; отправляет медиа в очередь модерации; ведёт статусы `pending/processing/ready/rejected`.

Условия использования данных:
- Тайлы `tile.openstreetmap.org` [31] предоставляются best-effort, без SLA. Обязательны атрибуция, корректный User-Agent/Referer и кэширование не меньше 7 дней. Префетч и «heavy use» запрещены; URL тайлов рекомендуется делать переключаемым.

- Ручной выбор «город → район» есть всегда: это fallback, и в native того же требует 5.1.1(iv) [51].
- Публично показываем только приблизительную точку.

## 3. UX лучших Mini Apps применительно к маркетплейсу услуг

### 3.1 Ориентиры (проверено)

- **Гайдлайны Telegram** [1]:
  - «mobile-first», компоненты повторяют стиль и поведение существующих UI-элементов;
  - 60 fps;
  - метки у всех полей и изображений;
  - динамические цвета темы, safe area и content safe area;
  - облегчённые эффекты на слабых Android.
- **Дистрибуция** [1]:
  - Main Mini App даёт кнопку «Launch app» и медиапревью в профиле бота (с переводами);
  - приложение попадает во вкладку Apps в поиске у тех, кто его запускал;
  - «Successful bots which enable a main Mini App and accept payments in Telegram Stars may be featured in the Telegram Mini App Store».
- **Масштаб:** 500 млн MAU у Mini Apps в июле 2024 [11]; в Mini Apps 2.0 (2024-11-17) добавлены fullscreen, home screen shortcuts, геолокация, подписки за Stars [10].
- **Проверенные примеры:**
  - @DurgerKingBot — официальный пример заказа;
  - @wallet — в описании бота «Trusted by 150M users»;
  - @tribute — подписки и донаты [12];
  - сам @BotFather теперь Mini App [3].
- **Не подтверждено в этой сессии:** Mini Apps крупных сервисных маркетплейсов и доставки (RU/СНГ/Балканы) — **[Допущение]**. Рекомендую ручной UX-аудит 5–10 приложений из вкладки Apps перед дизайном.

### 3.2 Навигация: tab bar или hub

| Модель | Когда | Для нас |
|---|---|---|
| Bottom tab bar, 3–5 пунктов | Много равноправных разделов, частое переключение | **Да**: Каталог · Заявки · «+ Создать» · Избранное · Профиль |
| Hub (главная с плитками) | Мало сценариев, редкое использование | Нет, только как главная для гостя |
| Гибрид | Tab bar на верхнем уровне, стек через BackButton ниже | **Рекомендуется** |

Правила:
- Tab bar скрываем, когда показан MainButton (формы, карточка с CTA): они делят нижнюю зону и safe area.
- Вкладки зависят от роли. Специалист видит «Лента заявок · Мои отклики · Профиль и прайс», клиент — клиентский набор. Переключение ролей — в профиле.
- Собственную верхнюю шапку с навигацией не рисуем: её роль выполняет хром Telegram.

### 3.3 Онбординг

1. Вход без экрана логина: initData → сессия.
2. Язык берём из `language_code`, с возможностью сменить на ru / sr-Latn / sr-Cyrl / en.
3. Три экрана максимум: город → роль («ищу специалиста» / «я специалист» / «ищу подработку») → готово. Кнопки Skip и Back обязательны (локальная база [37]).
4. Разрешения запрашиваем по контексту:
   - `requestWriteAccess` — когда пользователь хочет получать уведомления об откликах [1];
   - `requestContact` — только если нужен телефон;
   - геолокация — при открытии карты.

### 3.4 Каталог и лента заявок

- Сверху поиск, под ним ряд фильтр-чипов с переносом или «+N» (локальная база [37]). Полные фильтры — в bottom sheet, кнопка «Показать N» на MainButton.
- Фильтры и сортировка живут в URL (search params), чтобы ими можно было делиться и возвращаться назад.
- Skeleton при загрузке, cursor-пагинация, виртуализация.
- Pull-to-refresh по умолчанию не делаем: вертикальный свайп сворачивает или закрывает Mini App [1]. Обновляем кнопкой или по фокусу окна.
- Карточка специалиста: фото, рейтинг, цена «от … RSD», район, бейджи верификации, избранное.
- Карточка заявки: срочность, бюджет, район, число откликов, время публикации.

### 3.5 Формы (создание заявки, отклик, профиль и прайс)

- Мастер из шагов: категория → описание и фото → локация → бюджет и срочность → предпросмотр → «Опубликовать».
- MainButton ведёт по шагам «Далее» → «Опубликовать», BackButton возвращает на предыдущий шаг.
- Черновик автосохраняется в DeviceStorage; `enableClosingConfirmation` включён, пока форма «грязная».
- Валидация по blur, сводка ошибок после неудачной отправки, явный статус отправки: loading → success/error (локальная база [37]).
- Загрузка фото с прогрессом по каждому файлу, с повтором и удалением.

### 3.6 Пустые состояния, ошибки, доверие

- Пустое состояние объясняет ситуацию и предлагает действие. Например: «В вашем районе пока нет заявок — расширьте радиус или включите уведомления». Пустой белый экран недопустим [37].
- «Ничего не найдено» показываем вместе с подсказками, как ослабить фильтры [37].
- Доверие и безопасность:
  - «Пожаловаться» и «Заблокировать» — в overflow-меню карточек, профилей и чата;
  - статус «на модерации» у новых публикаций;
  - отзыв можно оставить только после выбора исполнителя.

### 3.7 Доступность

Локальная база [37]:
- touch targets 44 pt на iOS и 48 dp на Android, для web не меньше 24×24 CSS px;
- интервал между целями не меньше 8 px;
- метки у всех полей (совпадает с гайдлайнами Telegram [1]).

### 4.2 Насколько реальна «одна кодовая база» для TMA и native

**За:**
- Bluesky работает на одной RN-кодовой базе для web (через RNW), iOS и Android [49].
- Expo поддерживает web через RNW [42]. В SDK 58 async routes на web включены по умолчанию [39].
- DOM components (`'use dom'`) позволяют переносить web-код постепенно [40].

**Против (для нашего контекста):**
- **Размер и старт.** +74.5 KB gz только на RNW [24] плюс RN-абстракции поверх DOM. Холодный старт в WebView критичен: Mini App открывают «на секунду».
- **Вид.** Telegram-нативный вид строится на CSS-переменных темы и DOM-китах (TelegramUI, Konsta). RN-стили требуют JS-моста темы, и DOM-киты использовать нельзя.
- **Навигация.** Модели разные: BackButton/MainButton в Telegram против нативных stack-header и tab bar. Оболочки всё равно придётся делать раздельными.
- **Карты, медиа, auth, платежи.** Везде нужны платформенные реализации: MapLibre GL JS против нативных SDK, initData против OIDC/OTP/SiwA, Stars против IAP.
- **Особенности WebView.** Проблемы viewport, клавиатуры и safe areas сложнее чинить сквозь абстракцию RNW.
- **Сложность.** Компилятор Tamagui и молодой фреймворк One добавляют сложности команде из 1–2 человек.

**Правило решения.** Universal-подход имеет смысл только если выполнены все три условия:
1. native-приложение гарантированно выходит через 3–4 месяца после запуска TMA;
2. у команды есть опыт RN;
3. владелец готов к менее «телеграмному» виду Mini App.

Иначе выбираем **общий core + два UI**.

**Промежуточный путь на этапе 2.** Отдельные сложные web-экраны (редактор прайса, выбор точки на карте) можно временно встроить в Expo-приложение как DOM components. Ограничения [40]:
- нельзя передавать children и вкладывать нативные views;
- функции-пропсы асинхронные;
- **нет OTA-обновлений** для DOM components;
- Expo рекомендует «truly native views whenever possible».

Доля web-экранов увеличивает риск по 4.2 **[Допущение]**.

### 4.3 Монорепо: pnpm workspaces + Turborepo

```
repo/
  apps/
    tma/            # Telegram Mini App + standalone web (React + Vite)
    mobile/         # этап 2: Expo (iOS/Android)
  packages/
    api-client/     # orval: типы, fetchers, TanStack Query hooks, Zod-схемы, MSW-моки
    domain/         # бизнес-правила: статусы заявок, права, форматирование RSD/дат, расчёты
    hooks/          # headless-хуки сценариев (создание заявки, фильтры, избранное, отклик)
    platform/       # интерфейсы: auth, storage, haptics, share, openLink, location, nav-buttons, push
    i18n/           # ru / sr-Latn / sr-Cyrl / en, типизированные ключи, транслитерация, форматтеры
    design-tokens/  # цвета/отступы/радиусы/типографика → CSS vars (web) и JS-объект (RN)
    links/          # схема deep links: канонический URL ↔ startapp ↔ universal link
    ui-web/         # web-компоненты (обёртки над TelegramUI/Konsta → свои)
    config/         # tsconfig, lint/format presets
backend/            # Python (uv) — отдельный toolchain; экспортирует openapi.json
```

| Общее (пишется один раз) | Пишется заново для native |
|---|---|
| `api-client`, Zod-схемы, типы | Экраны и компоненты UI (RN primitives, FlashList 2.3.2) |
| `domain`, `hooks` (без импортов DOM/RN) | Навигация: Expo Router против TanStack Router |
| `i18n`: ресурсы, форматтеры, plural-полифилл для Hermes [27] | Реализации `platform`: `expo-secure-store`, `expo-notifications`, `expo-location` и т. д. |
| `design-tokens` | Медиа: `expo-image-picker` (системные пикеры), `expo-image-manipulator`, `expo-video` |
| `links`: схема deep links | Карты: `expo-maps` / `react-native-maps` / MapLibre RN |
| Схема аналитических событий, feature flags, remote config | Auth UI (OTP, Telegram OIDC, Sign in with Apple), IAP, push |

Тулинг:
- pnpm 12.6.0 и Turborepo 2.11.4 [23].
- Expo сам настраивает Metro для монорепо (SDK 52+). Изолированные установки поддерживаются с SDK 54, запасной вариант — `nodeLinker: hoisted` [41].
- Дубли React и RN ломают сборку и рантайм [41]. Поэтому одну версию React фиксируем на весь workspace через pnpm catalog/overrides. Практически это означает React той версии, что пинит текущий Expo SDK (19.2 в SDK 57), даже для TMA.
- Пайплайн: `openapi.json` → генерация `api-client` → typecheck/test обоих приложений → build. Ломающие изменения контракта ловим в CI, например oasdiff (Go CLI) **[Допущение: выбор инструмента]**.

### 4.4 Нативный стек и технические требования сторов

- **Expo SDK.**
  - SDK 57 (2026-06-30): RN 0.86, React 19.2; SDK живёт около года [38].
  - SDK 58 beta (2026-09-15): RN 0.88 RC, собрана под iOS 27 со scene-based lifecycle; в Expo Router стабильны data loaders и native tabs [39].
  - Этап 2 начинаем на стабильном SDK на тот момент. `react-native@latest` в npm — 0.87.1, но берём версию, которую пинит Expo.
- **Apple.**
  - С 2026-04-28 сборки делаются на iOS 26 SDK [62], с апреля 2027 — на iOS 27 SDK [63].
  - Приложения на iOS 27 SDK обязаны использовать scene-based lifecycle: в SDK 58 это по умолчанию, в SDK 57 включается вручную [38][39].
  - Новый форм-фактор iPhone Duo требует адаптивных лэйаутов [71].
- **Google Play:** новые приложения и обновления таргетят API 36 с 2026-08-31 [76].
- **EAS.** Free-план ($0 в месяц): 15 Android и 15 iOS сборок, OTA-обновления до 1K MAU. Платные планы Starter — $19 в месяц, Production — $199 в месяц [45]. Для разработки используем development builds, а не Expo Go: обновления Expo Go подолгу ждут одобрения в App Store [46].
- **Вход в native.**
  - Официальные нативные Telegram Login SDK [5] через свой Expo module или config plugin. Сторонний `expo-telegram-login-sdk` 1.0.0 — единственный релиз от 2026-04-25, незрелый [23].
  - Либо OIDC Authorization Code + PKCE через `expo-auth-session` [3].
  - OTP через Telegram Gateway по $0.01 за доставленный код [9] с SMS-fallback.
  - Sign in with Apple — `expo-apple-authentication`.
- **IAP.** `expo-iap` 5.8.0 или `react-native-iap` 16.7.0, либо RevenueCat (`react-native-purchases` 10.10.2) [23].

## 10. Открытые вопросы для владельца продукта

1. **Сроки этапа 2.** Если native нужен в пределах 3–4 месяцев после запуска TMA, стоит пересмотреть решение в пользу Expo universal (4.2).
2. **Модель монетизации специалистов.** Подписка, бусты, платные отклики, процент со сделки? Продаём ли цифровое в native с первого релиза (тогда IAP и 15–30%) или только в Telegram (Stars) и на вебе?
3. **Кросс-платформенный доступ к платным функциям.** Как PRO, купленный за Stars, работает в iOS и Android (3.1.3(b))?
4. **Встроенный чат** или связь через Telegram, телефон, Viber/WhatsApp? Встроенный чат — это больше модерации и рейтинг «Messaging and Chat».
5. **Отзывы при удалении аккаунта:** удалять полностью (прямое чтение правила Apple) или сохранять анонимно, если позволяет закон? Нужен юрист.
6. **Минимальный возраст пользователей** (предлагается 18+) и ответ на вопрос про social media в анкете Apple.
7. **Поддерживать ли iOS 13–16.3 в Mini App** (решаем по аналитике первых недель).
8. **Карта** — ключевой экран (MapLibre, единый стиль с native) или вспомогательный (Leaflet)? Какой провайдер тайлов и геокодинга, какой бюджет?
9. **Способы входа в native:** телефон (SMS или Telegram Gateway), Telegram OIDC (тогда плюс SiwA), Google? Нужен ли email?
10. **Юрлицо и аккаунты разработчика.** Есть ли сербское юрлицо с D-U-N-S для Apple и Google Organization? Может ли оно получать выплаты от Apple, Google и за Stars через Fragment?
11. **Регулируемые категории** (медицина, юристы, финансы) в каталоге? Это влияет на 5.1.1(ix) и модерацию.
12. **Web-оболочка вне Telegram** для местных пользователей: включаем в этап 1 (дёшево при архитектуре с адаптером `platform`)?
13. **Внешние AI-сервисы** для модерации и перевода UGC: какие, и готовы ли мы запрашивать отдельное согласие (5.1.2(i))?
