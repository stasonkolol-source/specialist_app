# Telegram-платформа для маркетплейса услуг: Bot API, Mini Apps, платежи

**Дата:** 26.09.2026 · **Документ:** research/02 · **Актуальная версия Bot API на дату:** 10.3 (24.08.2026)

**Контекст.** Маркетплейс специалистов в Сербии (ru/sr/en). Этап 1: бот + Telegram Mini App. Этап 2: нативные iOS/Android-клиенты к тому же API. Backend на Python + PostgreSQL, команда 1–2 разработчика.

**Обозначения:** [N] — источник из раздела «Источники»; **[Допущение]** — не подтверждено первоисточником, требует проверки.

---

## TL;DR

1. Актуальная версия — **Bot API 10.3 (24.08.2026)** [1][2]. С начала 2024 года вышло больше 20 релизов (7.1 → 10.3). Для нас важнее всего: 8.0 (fullscreen, safe areas, `shareMessage`, `LocationManager`, подписки за Stars, Ed25519-подпись `initData`), 9.0 (`DeviceStorage`/`SecureStorage`), 9.3–9.4 (топики в личных чатах с ботом), 10.0 (Business-боты без Premium, guest mode) и 10.2: с **20.07.2026** методы Mini App нельзя вызывать со страниц чужого origin.
2. Mini App запускается семью способами [3]. Нам нужны четыре: Main Mini App (кнопка в профиле бота и ссылка `t.me/<bot>?startapp=<код>`), menu button, inline-кнопки `web_app` в личке с ботом и URL-кнопки с t.me-ссылками в каналах и группах.
3. Deep-link-параметр `start` официально ограничен 64 символами `[A-Za-z0-9_-]` [4][7]. Для `startapp` официального лимита нет; community-документация называет 512 символов [39]. Поэтому коды делаем не длиннее 64 символов (`s_<id>`, `r_<id>`).
4. Авторизация строится на `initData`. Backend проверяет подпись (HMAC-SHA256, секрет `HMAC_SHA256(key="WebAppData", msg=bot_token)`) и `auth_date`: срок жизни Telegram не регламентирует, рекомендуем не больше 1 часа. Затем выдаёт собственные access/refresh-токены [3]. Третьи стороны могут проверять поле `signature` (Ed25519, публичный ключ Telegram) без токена бота [3].
5. **С 01.03.2026 у Telegram есть OpenID Connect** (`oauth.telegram.org`, Authorization Code + PKCE, scopes `openid profile phone telegram:bot_access`). **С апреля 2026 есть нативные SDK для iOS и Android** [9][10][11][13]. Это решает вход через Telegram в нативном приложении этапа 2 и связывание аккаунтов по Telegram `id`.
6. Бот не может написать пользователю первым. Нужен `/start` или явное согласие: `requestWriteAccess`, чекбокс у direct-link app или OIDC scope `telegram:bot_access` [3][6][8][9]. Бесплатные лимиты: около 1 сообщения в секунду в один чат, 20 в минуту в группу, около 30 в секунду глобально. Paid broadcasts поднимают потолок до 1000 сообщений в секунду по 0,1 Star за сообщение, но требуют **≥100 000 Stars на балансе и ≥100 000 MAU** [5][17].
7. **Топики в личных чатах с ботом есть.** С Bot API 9.3 (31.12.2025) можно отправлять сообщения в `message_thread_id`, с 9.4 (09.02.2026) бот сам создаёт топики через `createForumTopic` [2]. Relay-чат «клиент ↔ исполнитель» (один топик на диалог + `copyMessage`) реализуем, но есть три проблемы:
   - **включение режима добавляет комиссию 15% ко всем покупкам за Stars в боте** (ToS 6.2.6) [17];
   - режим работает только на клиентах, которые его поддерживают;
   - в нативное приложение этот механизм не переносится.
8. Business. С Bot API 10.0 (08.05.2026) любой пользователь может подключить бота к своему аккаунту (Settings → Chat Automation), Premium больше не нужен [2][14][25]. Для MVP это лишнее: высокий порог доверия, ограничения ToS 5.4, ответ (`can_reply`) возможен только в чатах, где за последние 24 часа было входящее сообщение [1][17].
9. Платежи.
   - Всё цифровое внутри Telegram продаётся **только за Stars (XTR)**; уводить на внешнюю оплату цифрового нельзя [17][22].
   - Разработчик получает примерно $0,013 за Star: пользователь платит $0,99 за 50 Stars, нам достаётся $0,65. Холд — 21 день.
   - Вывод — через Fragment, от 1000 Stars, в Gram (бывший Toncoin, переименован 15.06.2026) [17][22][23][24][48].
   - Подписки — только с периодом 30 дней и ценой до 10 000 Stars [1].
10. Оплату физической услуги (ремонт, маникюр) можно принимать через провайдеров Telegram Payments или вне Telegram. RSD в Telegram поддерживается (минимум 103,45 RSD) [20][21], но **провайдер для сербского юрлица не подтверждён**, а Stripe в Сербии недоступен [45]. На MVP оплату услуг в продукт не встраиваем.
11. Медиа. Через Bot API можно скачать до 20 MB и загрузить до 50 MB (фото — до 10 MB); с Local Bot API Server — до 2000 MB [1]. Рекомендуем загружать файлы из Mini App напрямую в S3 по presigned URL, а отправку медиа боту оставить как запасной путь.
12. Шеринг: `savePreparedInlineMessage` + `WebApp.shareMessage` (карточка с кнопкой), `t.me/share/url`, inline mode. С 10.0 есть **guest mode**: бота можно упомянуть в любом чате без добавления в участники [1][3][4][7].
13. Телефон можно получить тремя способами:
    - `requestContact` — бесплатно, номер Telegram-аккаунта;
    - OIDC scope `phone` — подтверждённый номер для веба и нативных клиентов;
    - Telegram Gateway — $0,01 за доставленный код, кредиты покупаются через Fragment [3][9][26][27][28].
14. Стек. Бот — **aiogram 3.31.0 (26.08.2026, Bot API 10.3)**; PTB 22.8 отстаёт (Bot API 10.0) [32][33]. Фронт — официальный `telegram-web-app.js` или **@tma.js/sdk 3.3.0 (14.07.2026)**. `@telegram-apps/sdk` (3.11.8, 10.2025) и `@twa-dev/sdk` (8.0.2, 02.2025) фактически не развиваются [36][37][38].
15. В витрину Mini App Store попадают приложения с Main Mini App, медиа-превью и приёмом Stars. Формальной подачи заявки нет, отбор на усмотрение Telegram [3][4].

## 2. Mini Apps

### 2.1 Способы запуска

| Способ | Настройка | Что получает Mini App | Применение у нас |
|---|---|---|---|
| **Main Mini App** | BotFather → Configure Mini App; медиа-превью на нескольких языках | `user`, `start_param`, `chat_type`/`chat_instance`; кнопка «Launch app» в профиле; попадание во вкладку Apps поиска у запускавших [3] | Основной вход. Ссылки `t.me/<bot>?startapp=<код>[&mode=compact]` |
| **Menu button** | `/setmenubutton` или `setChatMenuButton` (текст и URL на пользователя; с 7.6 — t.me-ссылка) [1][3] | Как у inline-кнопки (`query_id` → `answerWebAppQuery`) | Постоянная кнопка в чате с ботом |
| **Inline-кнопка `web_app`** | В сообщении бота; **только в личке user↔bot** [1] | `user`, `query_id` | Уведомления «Открыть заявку» с URL нужного экрана |
| **Reply keyboard `web_app`** | `KeyboardButton.web_app` | `sendData` до 4096 байт с закрытием приложения; **`initData` пустой** [3] | Не использовать для авторизованных сценариев |
| **Inline mode** | `answerInlineQuery(button=InlineQueryResultsButton)` | Нет доступа к чату; по документации `initData` пустой [3] | Выбор карточки для отправки в чат |
| **Direct link** | `/newapp` → `t.me/<bot>/<short_name>?startapp=&mode=` | `start_param`, `chat_type`, `chat_instance`; можно попросить write access чекбоксом при первом запуске [8] | Альтернатива Main App для ссылок из каналов и групп |
| **Attachment menu** | `/setattach` | `receiver`/`chat` | **Недоступно**: в проде только для крупных рекламодателей Telegram Ads [3] |

В каналах и группах кнопки `web_app` недоступны. Вместо них используем `url`-кнопку со ссылкой `t.me/<bot>?startapp=...` [1][3].

### 2.2 Параметр `startapp`

- Значение попадает в `initData.start_param` и в GET-параметр `tgWebAppStartParam` [3]. Роутинг можно делать сразу по GET-параметру, а доверять значению — после валидации `initData` (оно входит в подпись).
- **Лимиты.** Для `start` официально до 64 символов `A-Z a-z 0-9 _ -`, для бинарных данных — base64url [4][7]. Для `startapp` официальные документы лимит не указывают; tma.js называет 512 символов и тот же набор символов [39]. **[Допущение]**: 512 символов работают во всех клиентах. Держимся ≤64.
- Префиксы affiliate-ссылок (`starref_start_param_prefixes`, в примере конфигурации — `_tgr_`) зарезервированы [7][24]. Свои коды с них не начинаем.
- Режимы в ссылке: `mode=compact` (половина экрана) [3], в MTProto-спецификации ещё `mode=fullscreen` [7].

### 2.3 Режимы отображения, safe areas, тема

- **Высота.** Main app и direct links по умолчанию открываются на полную высоту. Compact включается параметром ссылки или настройкой BotFather. Fullscreen — через `requestFullscreen()`/`exitFullscreen()` (8.0); если он недоступен, придёт `fullscreenFailed` с `UNSUPPORTED` [3].
- **Viewport.** Для прижатых к низу элементов используем `viewportStableHeight`, а не `viewportHeight`; `expand()` разворачивает приложение [3].
- **Safe areas (8.0).** `safeAreaInset` (системные вырезы) и `contentSafeAreaInset` (элементы Telegram поверх контента в fullscreen) доступны как CSS-переменные `--tg-safe-area-inset-*` и `--tg-content-safe-area-inset-*` [3].
- **Тема.** `themeParams` (15 цветов: `bg_color`, `text_color`, `hint_color`, `link_color`, `button_color`, `secondary_bg_color`, `section_bg_color`, `destructive_text_color` и др.) доступны как `--tg-theme-*`. При смене темы приходит событие `themeChanged`. Для шапки, фона и нижней панели есть `setHeaderColor`, `setBackgroundColor`, `setBottomBarColor` [3].
- **Загрузка.** Splash (иконка и цвета для светлой и тёмной темы) настраивается в BotFather. `ready()` вызываем как можно раньше [3][4].
- **Android.** В User-Agent передаётся класс производительности `LOW`/`AVERAGE`/`HIGH`; на слабых устройствах стоит упрощать анимации [3].

### 2.5 Хранилища

| | CloudStorage (6.9) | DeviceStorage (9.0) | SecureStorage (9.0) |
|---|---|---|---|
| Где хранится | Серверы Telegram, синхронизация между устройствами | Локально на устройстве | iOS Keychain / Android Keystore, шифрование at rest |
| Лимиты | 1024 ключа на пользователя; ключ 1–128 символов `[A-Za-z0-9_-]`; значение до 4096 символов | 5 MB на пользователя | 10 элементов на пользователя; `restoreItem` для восстановления на устройстве |
| Для нас | Настройки UI, мелкие черновики | Кэш каталога, черновик заявки | Refresh-токен на мобильных |

Источник: [3]. Telegram **не гарантирует** сохранность этих данных (ToS 6.3) [17], поэтому источник истины — наш backend. **[Допущение]**: на Desktop и Web `SecureStorage` недоступен (в документации описан только iOS и Android).

### 2.6 Доступ к данным и устройству

- **`requestWriteAccess()`** (6.9) показывает нативный запрос разрешения писать пользователю; итог приходит в событии `writeAccessRequested` (`allowed`/`cancelled`). Текущее состояние видно в `initData.user.allows_write_to_pm` [3].
- **`requestContact()`** (6.9) — нативный запрос номера; статус `sent`/`cancelled`. Номер уходит боту как `contact`. Проверяем, что `contact.user_id == message.from.id` [1][3]. Официальный JS SDK передаёт в callback ещё и сырой подписанный `response` [31]. **[Допущение]**: его можно проверить тем же HMAC-алгоритмом, но это не документировано.
- **`LocationManager`** (8.0): `init()` → `getLocation()` → `LocationData` (широта, долгота, точность и т. д.); `openSettings()` — только по жесту пользователя [3]. Если доступа нет, пользователь выбирает город и район вручную.
- `BiometricManager` (7.2) подходит для подтверждения чувствительных действий, на MVP не нужен. Акселерометр, гироскоп и emoji status нам не нужны.

### 2.7 Шеринг, файлы, ярлыки

- **`savePreparedInlineMessage`** (backend: `user_id`, `InlineQueryResult`, флаги допустимых типов чатов) возвращает `PreparedInlineMessage` с `id` и `expiration_date`. Mini App вызывает `WebApp.shareMessage(id)`, открывается нативный выбор чата [1][3]. Ошибки: `UNSUPPORTED`, `MESSAGE_EXPIRED`, `USER_DECLINED` и др. [3].
- `switchInlineQuery(query, chat_types)` работает только при включённом inline mode [3].
- `shareToStory(media_url, params)`: подпись до 200 символов (у Premium — до 2048), ссылка-виджет только у Premium [3].
- `downloadFile({url, file_name})` (8.0) требует на сервере заголовки `Content-Disposition: attachment` и `Access-Control-Allow-Origin: https://web.telegram.org` [3].
- `addToHomeScreen()` / `checkHomeScreenStatus()` (8.0) возвращают статус `unsupported`, `unknown`, `added` или `missed` [3].

### 2.8 Ограничения WebView и чего в Mini App нет

Mini App — обычное веб-приложение во встроенном WebView. Клиенты разрабатываются независимо, поэтому поведение различается [3][40].

| Платформа | Что известно | Практический вывод |
|---|---|---|
| iOS | WebView с отладкой через Safari Web Inspector [3]. WebKit: без жеста автозапуск видео только muted, inline-воспроизведение на iPhone — с `playsinline` [47]. **[Допущение]**: iOS может перекодировать видео и конвертировать HEIC при выборе через `<input type=file>` | Видео с `playsinline muted`; проверить загрузку HEIC и больших видео |
| Android | В User-Agent — версия Telegram и класс производительности [3]. В community-трекере: при одновременных `accept` и `multiple` у `<input type=file>` не срабатывал `change` (#20, закрыт 12.2025), проблемы превью загружаемых фото (#67) [52] | Тест загрузки на 3–4 устройствах; не полагаться на превью из `<input>` |
| Desktop (Windows/Linux), macOS | Инспектор доступен только в beta-сборках [3]; на Linux у `<input type=time>` нет пикера (#22, открыт) [52] | Свои пикеры даты и времени; не делать desktop приоритетом |
| Web K/A | Mini App работает в iframe и общается через `postMessage` [40]; `downloadFile` требует CORS для `web.telegram.org` [3]. **[Допущение]**: third-party cookies и storage в iframe могут блокироваться | Авторизация через заголовок `Authorization`, не через cookies |

**Чего в Mini App нет:**
- push-уведомлений (только сообщения бота);
- фоновой работы (есть лишь `isActive` и `activated`/`deactivated` для свёрнутого приложения);
- доступа к чатам и контактам пользователя;
- отправки сообщений от его имени вне `answerWebAppQuery`, `shareMessage` и `switchInlineQuery`;
- оплаты цифрового, кроме Stars;
- SEO-индексации;
- гарантированного хранения на стороне Telegram.

Совместимость проверяем через `isVersionAtLeast()` и `platform`: у пользователей бывают старые клиенты [3].

### 2.9 Безопасность: защита origin (10.2)

С **20.07.2026** методы Mini App недоступны страницам, чей origin отличается от исходного домена приложения. Отключить защиту можно в BotFather, но тогда ответственность за ссылки на недоверенные сайты ложится на разработчика [2][16].

Выводы:
- весь фронт держим на одном origin;
- внешние страницы (оплата, OAuth) не смогут вызывать `Telegram.WebApp.*`;
- обычные API-запросы защита не затрагивает;
- ToS требует защищаться от «Arbitrary Data in WebAppData», поэтому всё из `initDataUnsafe` считаем недоверенным [17].

## 3. Аутентификация

### 3.1 Состав `initData`

| Поле `WebAppInitData` | Смысл |
|---|---|
| `query_id` | Сессия для `answerWebAppQuery` (inline-кнопка, menu button) |
| `user` (JSON `WebAppUser`) | Данные текущего пользователя |
| `receiver`, `chat` | Только attachment menu и join requests |
| `chat_type`, `chat_instance` | Контекст чата при запуске по direct link или ссылке на Main App |
| `start_param` | Значение `startapp` |
| `can_send_after`, `chat_join_request_query_id` (10.1) | Служебные |
| `auth_date` | Unix-время открытия Mini App |
| `hash` | HMAC-подпись для backend |
| `signature` | Ed25519-подпись для третьих сторон (8.0) |

Поля `WebAppUser` [3]:
- `id` — до 52 значащих бит, хранить как `BIGINT`;
- `first_name`, `last_name`, `username`;
- `language_code` — IETF-тег языка клиента;
- `is_premium`, `added_to_attachment_menu`, `allows_write_to_pm`;
- `photo_url` — `.jpeg` или `.svg`, зависит от настроек приватности; доступно всем с 8.0.

`initData` пуст при запуске из reply-клавиатуры и inline mode [3].

### 3.2 Проверка подписи (официальный алгоритм [3])

```text
pairs        = parse_query_string(init_data_raw)            # значения URL-декодируются
received     = pairs.pop("hash")
check_string = "\n".join(f"{k}={v}" for k, v in sorted(pairs))   # все поля, кроме hash (signature входит)
secret_key   = HMAC_SHA256(key="WebAppData", msg=BOT_TOKEN)
expected     = hex(HMAC_SHA256(key=secret_key, msg=check_string))
require constant_time_equal(expected, received)
require 0 <= now - int(pairs["auth_date"]) <= MAX_AGE           # MAX_AGE: см. 3.3
user = json.loads(pairs["user"])
```

Готовые реализации:
- `aiogram.utils.web_app.safe_parse_webapp_init_data` проверяет только подпись, **`auth_date` не проверяет** (проверено по исходникам 3.31.0) [32];
- альтернативы — `init-data-py` 1.0.0 и `telegram-webapp-auth` 3.2.1 [35].

Секрет Login Widget вычисляется иначе, как `SHA256(bot_token)`. Путать алгоритмы нельзя.

### 3.3 Срок жизни `auth_date`

Telegram лишь рекомендует проверять `auth_date` против устаревания и конкретного значения не даёт [3]. В документации tma.js пример — 3600 секунд [41].

Рекомендация:
- при обмене на сессию принимать `initData` не старше **1 часа**;
- допускать расхождение часов до 60 секунд;
- никогда не логировать `initData`.

`initData` — bearer-секрет: утёкшая строка переиспользуема до конца окна. Одноразовость по `hash` ломает перезагрузку страницы внутри Telegram, поэтому полагаемся на короткое окно, HTTPS и rate limit. **[Допущение]**: при каждом новом открытии Mini App приходит новый `initData`, а пока приложение открыто или свёрнуто, он не обновляется. Это надо учесть в refresh-логике.

### 3.4 Проверка третьей стороной (Ed25519)

```text
check_string = f"{BOT_ID}:WebAppData\n" + "\n".join(f"{k}={v}" for k, v in sorted(pairs без hash и signature))
require Ed25519_verify(TELEGRAM_PUBKEY, check_string, base64url_decode(signature))
```

Ключи Telegram [3]:
- prod — `e7bf03a2fa4602af4580703d88dda5bb59f32ed8b02a56c187fe7d34caed242d`;
- test — `40055058a4ee38156a06562e52eece92a771bcd8346a8c4615cb7376eddf72ec`.

В aiogram это `aiogram.utils.web_app_signature` (extra `signature`) [32]. Нам вариант пригодится, если валидацию вынесем в отдельный сервис без доступа к токену бота.

### 3.5 Обмен `initData` на сессию backend

1. Mini App отправляет `POST /v1/auth/telegram/webapp` с заголовком `Authorization: tma <initData>` (конвенция tma.js).
2. Backend проверяет подпись и `auth_date` (3.2–3.3).
3. Backend делает upsert в `users` и в `identities(provider='telegram', subject=<tg user id>)`. Заодно обновляет `username`, имя, `language_code`, `photo_url`, `allows_write_to_pm`.
4. Backend выдаёт свои токены:
   - access — JWT на 15 минут с нашим `user_id` в `sub`, `amr=["tg_webapp"]` и `bot_id`;
   - refresh — opaque-токен на 7–30 дней с ротацией, в БД хранится только хэш.
5. Клиент держит access в памяти. Refresh — в `SecureStorage` на мобильных, иначе в памяти или `DeviceStorage` (**[Допущение]**: защищённость `DeviceStorage` не документирована). Cookies не используем, поэтому CSRF не возникает.
6. При каждом запуске Mini App — повторный обмен. Refresh нужен для долгих и свёрнутых сессий. API лучше отдавать с того же origin, что и фронт (reverse proxy): так не нужен CORS.
7. Для dev/stage/prod — отдельные боты и токены. В сессии храним `bot_id`.

### 3.7 Связь Telegram-аккаунта с аккаунтом нативного приложения (этап 2)

- **Модель данных.** `users` связывается 1:N с `identities(provider, subject, …)`, уникальность по `(provider, subject)`. Провайдеры: `telegram`, позже `apple` и `phone`.
- **Вход в iOS через Telegram (OIDC и native SDK).** В ID-токене берём claim **`id`** (scope `profile`), а не `sub`: в примере документации это разные значения [9]. Найденная identity `telegram:<id>` открывает тот же аккаунт, что и в Mini App. **[Допущение]**: `id` из OIDC совпадает с `user.id` из Bot API; документация называет его «user ID». Проверить на тестовом аккаунте.
- **Привязка Telegram к существующему iOS-аккаунту** (например, созданному через Apple) делается тем же OIDC-потоком. Если identity уже есть у другого аккаунта, нужен сценарий слияния.
- **Fallback без OIDC.** Приложение открывает `t.me/<bot>?start=link_<одноразовый код>`, бот получает `/start link_…` и связывает аккаунты.
- **Apple 4.8.** Если Telegram — способ входа в основной аккаунт, приложение обязано предложить равноценный приватный вход (например, Sign in with Apple) [44].

## 4. Уведомления через бота

### 4.1 Когда бот может писать пользователю

Бот не начинает диалог первым: пользователь должен написать ему или добавить его в группу [6]. Разрешение появляется, если выполнено одно из условий:
- пользователь нажал `/start` или написал боту;
- дал согласие через `WebApp.requestWriteAccess()` [3];
- отметил чекбокс write access у direct-link app (`request_write_access`) [8];
- дал OIDC scope `telegram:bot_access` или `request_access=write` в библиотеке входа [9].

Флаг `allows_write_to_pm` в `initData` показывает текущее состояние. Блокировку бота видно по `my_chat_member` в личных чатах и по ошибке 403 при отправке [1].

### 4.2 Лимиты

| Лимит | Значение |
|---|---|
| Один чат | Не больше 1 сообщения в секунду; короткие всплески допустимы, дальше 429 [5] |
| Группа | Не больше 20 сообщений в минуту [5] |
| Массовые уведомления | Около 30 сообщений в секунду без paid broadcasts [5] |
| Paid broadcasts | До 1000 сообщений в секунду; 0,1 Star за каждое сообщение сверх бесплатных 30 в секунду, списывается только за доставленные; параметр `allow_paid_broadcast` [1][5] |
| Условия paid broadcasts | **≥100 000 Stars на балансе и ≥100 000 MAU** [5][17]. Во встроенной копии FAQ на странице Mini Apps ещё указано 10 000/10 000 — устаревшая версия |
| Хранение апдейтов | До 24 часов [1] |
| Сводка community-справочника | Те же значения; `start` ≤64 байт, текст ≤4096, подпись ≤1024 [51] |
| Webhook | Порты 443/80/88/8443, `max_connections` 1–100 (по умолчанию 40), заголовок `X-Telegram-Bot-Api-Secret-Token` [1] |

Стоимость paid broadcast: 0,1 Star × $0,013 ≈ $0,0013 за сообщение (по курсу вывода). Для нас неактуально: пороги недостижимы на старте. Обходить лимиты через несколько ботов или прокси ToS прямо запрещает (5.2(f)) [17].

### 4.3 Практики массовых рассылок

- **Очередь.** Таблица outbox в PostgreSQL (`SELECT … FOR UPDATE SKIP LOCKED`) и асинхронный воркер. Лимиты: глобальный token bucket около 25 сообщений в секунду и ≤1 сообщения в секунду на чат.
- **Обработка ответов.**
  - 429: брать `parameters.retry_after` [1] и ставить на паузу весь отправитель;
  - 5xx и таймауты: экспоненциальный backoff;
  - 400: не ретраить;
  - 403: помечать пользователя недоступным.
- **Идемпотентность.** Ключ `(user_id, event_id)`, при наплыве — дайджесты («5 новых откликов»), тихие часы по Europe/Belgrade.
- **Приоритеты.** Транзакционные уведомления («отклик на вашу заявку») идут раньше рекомендаций. Маркетинг — только тем, кто дал согласие: ToS запрещает спам (5.2(b)) [17].
- **Порядок величин.** Новая заявка для 200 подходящих специалистов уходит примерно за 8 секунд, для 10 000 — примерно за 6–7 минут.

### 4.4 Топики в личных чатах и relay-чат «клиент ↔ исполнитель»

**Что есть:**
- **10.10.2025** — анонс тредов и стриминга для ботов в клиентах [15].
- **Bot API 9.3 (31.12.2025).** `User.has_topics_enabled`; `message_thread_id` в личных чатах для всех `send*`, `copyMessage(s)`, `forwardMessage(s)` и `sendChatAction`; `editForumTopic`, `deleteForumTopic`, `unpinAllForumTopicMessages` в личке [2].
- **Bot API 9.4 (09.02.2026).** Бот сам создаёт топик (`createForumTopic`: имя 1–128 символов, цвет из фиксированного набора или разрешённый custom emoji). В BotFather можно запретить пользователям создавать и удалять топики (`allows_users_to_create_topics`) [1][2].
- Режим включается в BotFather [4].

**Цена.** По ToS 6.2.6, пока топики в личных чатах включены, **Telegram удерживает 15% со всех покупок за Stars в этом боте** [17]. Режим работает, только если клиент пользователя его поддерживает [17].

**Схема relay «один топик на диалог»:** создаём диалог `C` → `createForumTopic` в личке клиента («Люстра · Марко») и в личке исполнителя («Люстра · Анна, Лиман») → входящие в топике A пересылаем через `copyMessage(..., message_thread_id=B)` → каждое сообщение сохраняем в БД.

Оценка применимости:

| Аспект | Оценка |
|---|---|
| Реализуемость | Да: весь нужный набор методов есть в 9.3–9.4 [1][2] |
| Плюсы | Нативный UX Telegram, push-уведомления, медиа и голосовые без собственного UI чата |
| Комиссия | 15% со Stars — существенно, если будем продавать продвижение или подписки за Stars [17] |
| Лимиты | Лимит около 1 сообщения в секунду на чат общий для всех топиков пользователя. **[Допущение]**: лимит считается на чат, а не на топик |
| Надёжность | Пользователь может удалить топик (если не запрещено), бот должен пересоздавать его лениво. Сообщения в хранилище бота могут удаляться [6], поэтому источник истины — наша БД. **[Допущение]**: события удаления сообщений в личке боту не приходят (есть только для business) |
| Совместимость | Старые клиенты — **[Допущение]**: как отобразится, неизвестно; нужен тест |
| Этап 2 | В iOS не переносится; понадобится свой чат, а топики останутся лишь одним каналом доставки |
| Антифрод | Модерация (обмен телефонами, ссылки) возможна: весь трафик идёт через backend |

Варианты коммуникации:

| Вариант | Суть | Сложность | Контроль платформы | Перенос в iOS |
|---|---|---|---|---|
| **A. Передача контакта** | После выбора исполнителя показываем `@username`, `tg://user?id` (работает не при всех настройках приватности [1]) или телефон с согласия | Минимальная | Низкий: сделка уходит из продукта | Да |
| **B. Relay через топики** | См. выше | Средняя | Высокий | Только модель данных |
| **C. Чат в Mini App + уведомления ботом** | WebSocket или polling; бот шлёт «Новое сообщение» с `web_app`-кнопкой на экран диалога | Высокая | Высокий | Полный |

### 4.5 Новые форматы сообщений, полезные для уведомлений

- **Цветные кнопки** `style` `success`/`danger`/`primary` (9.4) [1].
- **`date_time`-сущность** (9.5): «сегодня в 19:00» показывается в часовом поясе получателя [2].
- **`DisabledButton`** (10.3): для закрытой заявки кнопку «Откликнуться» делаем неактивной через `editMessageReplyMarkup` [1][2].
- **Rich messages** (10.1–10.3): таблицы и кнопки внутри сообщения; подходят для дайджестов [2].

## 5. Telegram Business и Chat Automation

- С Bot API 10.0 (08.05.2026) Business-ботам **не нужен Premium**. В интерфейсе это Settings → Chat Automation: любой пользователь подключает бота и выбирает, к каким чатам тот получает доступ [2][14][25].
- Бот должен включить Secretary Mode в BotFather [4]. Он получает `business_connection`, `business_message`, `edited_business_message`, `deleted_business_messages` и отвечает с `business_connection_id` [1][4].
- **Права `BusinessBotRights`:**
  - `can_reply` — отправка и редактирование только в чатах, где за 24 часа было входящее сообщение;
  - `can_read_messages`, `can_delete_*`;
  - управление именем, био и фото;
  - Stars, подарки, stories [1].
- **ToS 5.4.** Нельзя использовать данные переписки вне заявленной функции, передавать их третьим сторонам без согласия и скрывать действия бота от владельца. Нарушение грозит баном [17].

**Есть ли смысл для нас.** Потенциально это Pro-функции для специалиста:
- автоответ клиентам в личке («я на объекте, вот мой профиль и свободные слоты»);
- превращение входящих диалогов в заявки;
- импорт отзывов.

Но бот увидит личную переписку специалиста: это высокий порог доверия, работа с персональными данными и строгие требования ToS. **На MVP не делаем**, вернуться после появления платящих специалистов.

Смежная возможность — `getUserPersonalChatMessages` (10.0): до 20 последних сообщений из личного канала пользователя, закреплённого в профиле [1]. С согласия специалиста это можно использовать для импорта портфолио.

## 6. Платежи

### 6.1 Правило «цифровые товары и услуги — только Stars»

- **ToS 6.2.** Всё цифровое продаётся только за Stars. Определение «цифрового» — по правилам Apple и Google. Нарушителю приходит уведомление, затем бот скрывают из store-версий Telegram или удаляют [17].
- **FAQ по Stars.** Собственный сайт с оплатой не освобождает от Stars для продаж внутри Telegram, криптовалюта тоже не разрешена [22]. Криптофункции в Mini Apps допускаются только на TON (ToS 7) [17].
- **Обязательно:** команда `/paysupport`, возвраты через `refundStarPayment`, `/terms` и `/support` по live-чеклисту [17][22].

- **Региональные ограничения.** В конфигурации есть флаг `stars_purchase_blocked` [23][24]. Доступность покупки Stars в Сербии — **[Допущение]**.

### 6.3 Подписки за Stars

- Создаются через `createInvoiceLink(currency="XTR", subscription_period=2592000)`. Сейчас допустим только период 30 дней, цена — до 10 000 Stars [1].
- В `SuccessfulPayment` приходят `is_recurring`, `is_first_recurring`, `subscription_expiration_date`. Отмена — `editUserStarSubscription`. Изменения подписки — апдейт `BotSubscriptionUpdated` (10.2) [1][2].
- Пример: Pro-план специалиста за 500 Stars в месяц стоит пользователю около $9,99, нам приносит около $6,50. Если включены топики в личке, ещё −15% (4.4).

### 6.4 Физические товары и услуги (Telegram Payments)

- Telegram не берёт комиссию и не обрабатывает платежи: провайдер подключается в BotFather → Payments, `provider_token` передаётся в `sendInvoice`/`createInvoiceLink` [20]. В документации заявлено «более 20 провайдеров, 200+ стран», для тестов — Stripe TEST MODE [20].
- **Какие провайдеры.** Официального публичного списка нет, он виден только в BotFather. Сторонний обзор называет Smart Glocal, Unlimint, Tranzzo, Paykassma, YooMoney, Sberbank, PSB, Bank 131, Payme, CLICK, LiqPay, ECOMMPAY, PayMaster, iPay88, Freedom Pay, Chapa и др. [46]. В основном это СНГ, Азия и Африка.
- **Сербия.** Stripe не обслуживает компании из Сербии (страны нет в списке на 26.09.2026) [45]. **[Допущение]**: провайдера, принимающего сербское юрлицо, в BotFather нет. Проверить вручную и у Unlimint и ECOMMPAY.
- **RSD.** Поддерживается: минимум 103,45 RSD, максимум 1 034 456,90 RSD, два знака после запятой [20][21].
- Инвойсы можно отправлять в чаты любого типа; на `pre_checkout_query` надо ответить за 10 секунд [20].
- **App Store.** Физические услуги, потребляемые вне приложения, **обязаны** оплачиваться не через IAP (3.1.3(e)) [44]. Значит, и в iOS оплата самой услуги идёт через внешний эквайринг.

### 6.5 Что запрещено (ToS) и можно ли вести на внешнюю оплату

Запрещено [17]:
- спам и навязчивые рассылки;
- выдавать себя за Telegram или другую организацию, в том числе использовать знаки Telegram в названии и брендинге (8.1);
- вводить пользователей в заблуждение (MLM, фишинг, запрос пароля или OTP);
- обходить лимиты и модерацию (прокси, чужие токены);
- malware, нелегальные и регулируемые товары, язык вражды;
- UI, который имитирует системные уведомления (5.3);
- сбор данных сверх необходимого, в том числе для обучения AI (4.3).

По пользовательскому соглашению Mini Apps Telegram не обрабатывает платежи и не участвует в спорах: претензии идут к нам как к поставщику [18].

Обязательно [17][30]:
- privacy policy (по умолчанию действует стандартная; свою прописывают в BotFather);
- удаление данных по запросу (4.2);
- шифрование at rest и уведомление об утечках (4.4).

Внешняя оплата:

| Что продаём | Внешняя оплата |
|---|---|
| Цифровое (продвижение, подписка, доступ к заявкам) | **Нельзя** внутри Telegram: только Stars [17][22] |
| Физическое (сама услуга мастера) | **Можно**: провайдер Telegram Payments или свой эквайринг [17][20]. **[Допущение]**: переход через `openLink` на внешнюю платёжную страницу для физических услуг допустим — прямого запрета нет. Учесть, что внешняя страница не вызывает WebApp-методы (2.9) |

### 6.6 Affiliate programs

- Партнёрская программа работает только для покупок за Stars в нашем Mini App.
- Комиссия и срок задаются при создании и потом не уменьшаются; в примере конфигурации допустимая комиссия от 0,1% до 80% [19][24].
- Ссылки вида `t.me/<bot>?ref=…` и `t.me/<bot>?start=_tgr_…` [7]. Партнёрские Stars холдятся 21 день; перенаправлять покупки в обход комиссии запрещено [19].
- Для нас это имеет смысл, только если будем продавать цифровое за Stars. Собственную реферальную программу (клиент приводит мастера) делаем своими `startapp`-кодами.

### 6.7 Что это значит для модели монетизации

| Модель | Классификация | В Telegram | В iOS (этап 2) |

## 7. Медиа

### 7.1 Лимиты Bot API

| Операция | Лимит |
|---|---|
| Скачивание (`getFile`) | До 20 MB; ссылка живёт не меньше 1 часа [1] |
| Загрузка multipart | Фото до 10 MB (сумма сторон ≤10 000, соотношение ≤20), остальное до 50 MB [1] |
| Загрузка по URL | Фото до 5 MB, остальное до 20 MB [1] |
| Повтор по `file_id` | Без лимита; `file_id` уникален для бота и не переносится между ботами [1] |
| Local Bot API Server | Загрузка до 2000 MB, скачивание без лимита, локальные пути, HTTP-webhook [1] |
| Альбом (`sendMediaGroup`) | 2–10 элементов [1] |
| Текст и подпись | Сообщение 1–4096 символов, подпись 0–1024 [1] |

### 7.2 Загрузка из Mini App

- Обычный `<input type="file" accept="image/*,video/*" multiple>` работает внутри WebView, но реализации различаются: известны проблемы на Android (2.8) [52]. Для iOS отдельно проверяем HEIC и большие видео.
- На клиенте:
  - уменьшаем фото до длинной стороны около 2048 px, JPEG или WebP;
  - **удаляем EXIF**: иначе утечёт геолокация дома клиента;
  - показываем прогресс;
  - видео загружаем multipart-частями с повторами.

### 7.3 Presigned S3 или отправка медиа боту

| Критерий | Presigned URL в наш S3 | Медиа в чат бота |
|---|---|---|
| Размер | Ограничиваем сами (например, фото ≤15 MB, видео ≤200 MB) | Без Local Bot API Server скачать можно только ≤20 MB |
| UX | Не выходим из Mini App, есть прогресс | Переключение в чат; альбом приходит отдельными сообщениями по `media_group_id`, нужна привязка к черновику |
| Качество | Контролируем сами | Telegram сжимает фото; «как файл» — без сжатия |
| Переносимость | Тот же API для iOS | Только Telegram |
| Сложность | CORS на бакете для origin Mini App, клиентская обработка, антивирус и модерация | Обработка апдейтов, `getFile`, копирование в S3 |

**Вывод:** основной путь — presigned S3. Бот принимает фото как запасной путь («не получается загрузить — пришлите фото сюда»).

### 7.4 Видео в WebView

- Отдаём MP4 (H.264/AAC, `faststart`) с постером, `preload="metadata"`. Для автоплея превью — `playsinline muted` (политики WebKit [47]); range-запросы S3 и CDN.
- Длинные ролики: HLS нативно работает в iOS, для остальных — hls.js. **[Допущение]**: кодеки Desktop Linux (WebKitGTK) могут не поддерживать H.264, это не приоритетная платформа.
- Портфолио: лимит длительности (например, 60 с) и серверное перекодирование через ffmpeg.

## 8. Deep links, шаринг и телефон

### 8.1 Схема ссылок

| Назначение | Ссылка |
|---|---|
| Профиль специалиста | `https://t.me/<bot>?startapp=s_<base62id>` |
| Заявка | `https://t.me/<bot>?startapp=r_<id>`; быстрый отклик — `&mode=compact` |
| Реферал | `https://t.me/<bot>?startapp=s_<id>_i<refcode>` (≤64 символов) |
| Команда боту | `https://t.me/<bot>?start=<param>` (≤64 base64url-символов) [7] |
| Связка аккаунтов | `https://t.me/<bot>?start=link_<nonce>` |
| Шеринг текста и ссылки | `https://t.me/share/url?url=<url>&text=<text>` через `openTelegramLink` [7] |

Если у бота нет Main Mini App, клиент по ссылке `t.me/<bot>?startapp` откроет обычный чат с ботом [7].

### 8.2 Как поделиться карточкой специалиста или заявкой

1. **`shareMessage`.** Backend создаёт `savePreparedInlineMessage` с `InlineQueryResultPhoto` (фото, имя, рейтинг, цена от …) и `url`-кнопкой «Открыть в приложении» на `startapp`-ссылку. Пользователь выбирает чат нативно [1][3]. Подготовленное сообщение истекает, поэтому создаём его непосредственно перед шерингом.
2. **Inline mode.** `@bot электрик лиман` в любом чате показывает карточки [1][4].
3. **Guest mode (10.0).** Упоминание бота в любом чате (например, в группе «Русские в Нови-Саде») даёт `guest_message`; ответить можно один раз через `answerGuestQuery`; в сообщении можно упомянуть до 3 guest-ботов [1][4]. Сильный канал в комьюнити-чатах, но нужна осторожность с нормами этих групп.
4. **Веб-ссылка с Open Graph** (`https://<домен>/s/<id>`) даёт превью конкретной карточки в Telegram, WhatsApp и Viber и редиректит в Mini App, а без Telegram — на веб-страницу. **[Допущение]**: превью ссылки `t.me/<bot>?startapp=…` показывает общую информацию о боте или приложении, а не конкретную карточку.
5. **Публикация заявок в городской канал** (без точного адреса): `url`-кнопка на `startapp`, потому что `web_app`-кнопки в каналах недоступны [1].

### 8.3 Телефон

| Способ | Что даёт | Цена | Ограничения |
|---|---|---|---|
| `requestContact` / `KeyboardButton.request_contact` | Номер Telegram-аккаунта, приходит боту как `contact` [1][3] | 0 | Пользователь может отказаться; проверять `contact.user_id == from.id` |
| OIDC scope `phone` | `phone_number` + `phone_number_verified` в ID-токене [9] | 0 | Нужен Telegram-аккаунт и согласие |
| Telegram Gateway API | Код подтверждения в Telegram на любой номер с аккаунтом [26][27] | **$0,01 за доставленный код**; `ttl` 30–3600 с, недоставленные коды автоматически возвращаются (с 26.02.2025) [27][29] | Кредиты покупаются через Fragment и не возвращаются [28]. ToS допускает разные цены по странам и говорит об оплате за отправку, API-документация — о возврате при недоставке [27][28]. Для пользователей без Telegram нужен SMS-fallback |

## 10. UX-паттерны, каталог и аналитика

### 10.1 UX-паттерны

Опираемся на гайдлайны Telegram [3] и возможности платформы:
- **Быстрый старт.** Кастомный splash, `ready()` сразу после первого экрана, скелетоны, кэш каталога в `DeviceStorage`, учёт класса производительности Android [3][4].
- **Нативная навигация.** `BackButton` вместо своей стрелки; одно главное действие на экран в `MainButton`, второстепенное в `SecondaryButton`; haptics на подтверждениях.
- **Тема.** Только `--tg-theme-*`, корректный dark mode, safe areas в fullscreen.
- **Мастер создания заявки:** категория → описание и фото → район → когда (срочность) → бюджет в RSD → язык общения. Черновик сохраняется автоматически, при попытке закрыть — `enableClosingConfirmation`.
- **Контекстные разрешения:**
  - `requestWriteAccess` — после публикации заявки («Сообщать об откликах?»);
  - `requestContact` — только перед передачей телефона;
  - `LocationManager` — с объяснением зачем, иначе ручной выбор района.
- **Уведомления ведут на конкретный экран.** `web_app`-кнопка с URL экрана или `startapp` с `mode=compact` для быстрого отклика.
- **Возврат.** Ярлык на домашний экран (`addToHomeScreen`) — после 2–3 сессий; шеринг карточек через `shareMessage`.
- **Язык.** Первичный выбор по `language_code`, затем явный переключатель ru/sr/en. Имя, описание и команды бота локализуются через `setMyName`, `setMyDescription`, `setMyShortDescription`, `setMyCommands` с `language_code` (ISO 639-1) [1]. Медиа-превью Main Mini App тоже поддерживают несколько языков [3].
- **Эталон нативного вида** — официальные @DurgerKingBot (демо заказа еды) и Mini App @BotFather [3][16].

### 10.2 Каталог Mini Apps

- **Mini App Store** («Apps» в поиске) собирается Telegram. Шансы на featured повышают Main Mini App, качественные медиа-превью и **приём оплаты в Stars**; выбор остаётся на усмотрение Telegram [3][4][17].
- Боты с Main Mini App показываются во вкладке Apps у тех, кто их уже запускал [3].
- По данным Telegram, больше 500 млн из 950 млн пользователей ежемесячно пользуются Mini Apps. Страница без даты; на странице логина указан уже «1 млрд пользователей» [4][9].
- Сторонний каталог Telegram Apps Center ориентирован на TON и крипту и нам не подходит.

### 10.3 Аналитика

- **Telegram Mini Apps Analytics SDK** (`@telegram-apps/analytics` 1.6.4, 22.01.2026; ключ выдаёт TON Builders). Собирает анонимные запуски и события TON Connect и нужен в основном для рейтинга в TON-каталогах [42][43]. Нам не нужен.
- **Своя продуктовая аналитика:** события с backend и фронта, атрибуция по `start_param` (подписан, можно доверять после валидации), воронка бота (`/start` → разрешение писать → первая заявка). Учитываем GDPR и сербский ZZPL — без лишних персональных данных и с согласием.

## Рекомендации для нашего продукта

1. **Один бот, один Main Mini App.** Main Mini App включаем в BotFather; menu button указывает на тот же SPA. Все deep links — `t.me/<bot>?startapp=<код>`, коды ≤64 символов `[A-Za-z0-9_-]` без префикса `_tgr_`. *Почему:* кнопка в профиле, вкладка Apps и медиа-превью доступны только Main App; лимит `startapp` официально не зафиксирован.
2. **Авторизация.**
   - Своя серверная проверка `initData`: HMAC, `auth_date` ≤1 ч, constant-time сравнение.
   - Обмен на свои JWT (15 мин) и ротируемый refresh.
   - Таблица `identities` с первого дня.
   - *Почему:* API-first и будущий вход через OIDC и Apple в iOS.
3. **Бот на aiogram 3.31.x** в webhook-режиме: `secret_token`, узкий `allowed_updates`, Redis для FSM. Бот — тонкий клиент к тому же API, бизнес-логика только в backend.
4. **Уведомления через outbox в PostgreSQL** и воркер с лимитами около 25 сообщений в секунду глобально и 1 в секунду на чат. Обработка 429 и 403, дайджесты, тихие часы. Разрешение писать запрашиваем контекстно и храним `allows_write_to_pm`.
5. **Коммуникация клиент ↔ исполнитель на MVP — вариант A:**
   - структурированный отклик (цена, срок, комментарий) в Mini App;
   - после выбора исполнителя — обмен контактами с согласия;
   - backend-модель `conversations` и `messages` закладываем сразу.

   Релей через топики (B) — только как эксперимент и только пока не продаём за Stars (комиссия 15%). Для этапа 2 — свой чат (C).
6. **Медиа.** Presigned upload в S3 из Mini App: сжатие и удаление EXIF на клиенте, серверное перекодирование видео, CORS на бакете для origin Mini App. Бот — запасной канал для фото (≤20 MB). Local Bot API Server на MVP не поднимаем.
7. **Платежи на MVP не встраиваем.** Клиент платит мастеру напрямую. Когда появятся платные функции для специалистов:
   - в Telegram — только Stars (подписка на 30 дней или разовые бусты);
   - заранее решаем с бухгалтером вопрос вывода через Fragment в Gram;
   - оплату самой услуги подключаем только после подтверждения провайдера для нашего юрлица и RSD.
8. **Шеринг.** `shareMessage` с подготовленной карточкой, запасной путь — `t.me/share/url`. Веб-страница карточки с OG-метатегами для Viber и WhatsApp. Позже — inline mode и guest mode для комьюнити-чатов.
9. **Телефон.** В Telegram — `requestContact` (бесплатно) и только когда реально нужен. В iOS — OIDC scope `phone`, для пользователей без Telegram — Gateway ($0,01) с SMS-fallback.
10. **Этап 2.** «Войти через Telegram» — через официальный native SDK (OIDC, claim `id` при scope `profile`) плюс Sign in with Apple (Apple 4.8). Fallback для связки — `start=link_<nonce>`.
11. **Безопасность и соответствие правилам.**
    - Весь фронт на одном origin (защита с 20.07.2026), CSP.
    - Своя privacy policy в BotFather; обработка `/paysupport` и `/terms`, если появятся Stars.
    - Шифрование персональных данных at rest, удаление данных по запросу.
    - Без слова «Telegram» в названии и брендинге.
12. **Тестирование.** Тестовое окружение Telegram (отдельные аккаунт и бот, допускается HTTP), отладка WebView на iOS и Android [3]. Матрица клиентов: iOS, Android (включая слабый девайс), Desktop Windows, macOS, Web A/K.
13. **Витрина.** Медиа-превью Main Mini App на ru/sr/en с самого запуска. Для featured нужен приём Stars, так что к витрине вернёмся вместе с монетизацией.

## Риски

| Риск | Влияние | Как снижаем |
|---|---|---|
| Односторонние изменения правил Telegram: ToS 13 допускает любые изменения без уведомления. Примеры — порог paid broadcasts вырос с 10k до 100k, комиссия 15% за топики | Высокое | Telegram — один из клиентов API-first backend; сторонние механики (топики, Business) не делаем ядром |
| Классификация платных функций для специалистов как «цифровых»: только Stars или IAP, потеря около 35% выручки, вывод в крипте | Высокое для монетизации | Модель с комиссией за физическую услугу; ранняя консультация по правилам Apple и Google |
| Нет платёжного провайдера для Сербии и RSD в Telegram Payments | Среднее | Оплату услуг на MVP не встраиваем; внешний эквайринг — после выбора юрлица |
| Вывод Stars только через Fragment в Gram: налоги, учёт, региональная доступность | Среднее | Консультация бухгалтера до запуска Stars; альтернатива — тратить Stars на Telegram Ads по $0,02 |
| Утечка `initData`: bearer-строка переиспользуема | Среднее | Окно ≤1 ч, HTTPS, не логировать, rate limit, короткий access-токен |
| Фрагментация клиентов: старые версии, desktop, web | Среднее | `isVersionAtLeast`, запасные пути для file input, геолокации и хранилищ, тестовая матрица |
| Бот не может писать без разрешения; блокировки; лимит 30 сообщений в секунду | Среднее | Контекстный `requestWriteAccess`, очередь, дайджесты, учёт 403 |
| История сообщений у бота не гарантирована, CloudStorage не гарантирован [6][17] | Среднее | Источник истины — наша БД |
| Защита origin с 20.07.2026 ломает многодоменный фронт | Низкое | Единый origin, API за reverse proxy |
| Приватность: EXIF-геолокация в фото, телефоны, ZZPL/GDPR, требования ToS 4.x | Высокое | Удаление EXIF, минимизация данных, privacy policy, процедуры удаления |
| Business-бот видит личную переписку специалиста (ToS 5.4) | Высокое при реализации | Не делаем на MVP |
| Расхождения официальной и community-документации (лимит `startapp`, строка валидации `requestContact`) | Низкое | Консервативные лимиты, опора на официальные механизмы |
| Отставание библиотек (PTB поддерживает только 10.0) | Низкое | aiogram; сырые вызовы Bot API для новых методов |

## Открытые вопросы для владельца продукта

1. Нужна ли на MVP переписка через платформу (антиобход, отзывы только по реальным сделкам) или достаточно обмена контактами после выбора исполнителя? Ответ определяет выбор между вариантами A, B и C и объём работ.
2. Модель монетизации на первые 6–12 месяцев: бесплатно для всех, комиссия со сделки или платные функции для специалистов? Готовы ли получать выручку в Stars с выводом в Gram (крипто) и с потерей около 35%?
3. Где регистрируется юрлицо (Сербия, ЕС, другое)? От этого зависят доступные провайдеры (Stripe для Сербии недоступен) и эквайринг в RSD.
4. Нужна ли обязательная верификация телефона: для специалистов, для клиентов? На каком этапе — при регистрации или перед контактом?
5. Разрешаем ли публичную публикацию заявок в городских каналах и группах (без точного адреса) и продвижение через guest mode и inline mode в чужих комьюнити-чатах?
6. Сербский язык — латиница, кириллица или оба варианта? Нужен ли английский на старте?
7. Лимиты портфолио: сколько фото и видео, максимальная длина и размер видео? От этого зависят бюджет хранения и перекодирования.
8. Сроки этапа 2 (iOS)? Согласны ли на обязательный Sign in with Apple рядом с Telegram-входом?
9. Интересна ли в перспективе Pro-функция «подключить бота к личному Telegram специалиста» (Business, автоответы)?
10. Важно ли попасть в витрину Mini App Store? Это фактически требует приёма оплаты в Stars.
11. Бюджет на верификацию: Gateway ($0,01 за код, кредиты через Fragment) или SMS-провайдер для пользователей без Telegram?
12. Кто юридически отвечает за privacy policy, сроки хранения и удаление данных (ToS 4.2, ZZPL)?
