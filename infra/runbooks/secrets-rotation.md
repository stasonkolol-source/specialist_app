# Ротация секретов

Когда: плановая ротация (ARCHITECTURE §13.5), утечка или подозрение на неё, K43 перед публичным
запуском (всё, что когда-либо проходило через чат). Правила обращения с секретами —
[OWNER_CHECKLIST](../../docs/OWNER_CHECKLIST.md), раздел «Правила обращения с секретами»: значения
не печатаются, новое значение сразу уходит в менеджер паролей (K10a).

## 0. Порядок для любого секрета

1. Выпустить новое значение (`make gen-secret NAME=… ENV=stage|production` или в консоли сервиса).
2. Сохранить копию в менеджер паролей.
3. Записать в секреты окружения (GitHub / SOPS) и выкатить: `kamal deploy -d <env>` или
   `kamal env push` + `kamal app boot`.
4. Проверить, что работает новое значение (колонка «Проверка»).
5. Отозвать старое значение. При утечке — **сначала отозвать**, потом проверять: простой лучше,
   чем чужой доступ.
6. Отметить в журнале ротаций (дата, кто, причина) — таблица в конце файла.

## 1. Что и как ротируется

| Секрет | Переменная | Как | Проверка | Особенности |
|---|---|---|---|---|
| Токен бота | `TELEGRAM_BOT_TOKEN` | @BotFather → `/revoke` → бот → новый токен | бот отвечает на `/start`; Mini App входит (initData подписан новым токеном) | Старый токен умирает сразу; initData, выданные до ротации, перестают проверяться — пользователи перезаходят |
| Секрет webhook | `TELEGRAM_WEBHOOK_SECRET` | `make gen-secret`, затем `setWebhook` с новым `secret_token` (делает старт `bot`/`web`) | `getWebhookInfo` без ошибок, апдейты доходят | Между deploy и `setWebhook` апдейты с прежним секретом отклоняются — Telegram повторит |
| Ключи подписи JWT | `JWT_KEYS` | `cli jwt-keys --rotate`: новый `kid` подписывает, прежний только проверяет | вход, обновление сессии | Прежний ключ убрать следующим релизом через ≥ 15 мин (TTL access). При утечке — убрать сразу: все access-токены станут недействительны, клиенты обновятся через refresh |
| Refresh-сессии | — (БД) | при утечке ключей или токенов — отозвать сессии: `identity.sessions` → `revoked_at = now()` | Mini App перевходит по initData | Пользователь в Mini App этого не заметит: вход по initData автоматический |
| Пароли ролей БД | `DB_DSN`, `DB_MIGRATOR_DSN` | `ALTER ROLE app PASSWORD …` (значение — из `make gen-secret`, не в историю psql) | `/up`, `alembic current` | Старый пароль перестаёт работать сразу: сначала секреты, затем `ALTER ROLE`, затем boot |
| Ключ HMAC | `APP_HASH_KEY` | **не ротируется** планово: смена «забудет» хэши удалённых аккаунтов | — | При утечке — новый ключ и принять потерю антифрод-хэшей (12 мес) |
| Ключи R2 / S3 | `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Cloudflare → R2 → API Tokens: новый токен на бакеты окружения, старый удалить | загрузка фото, превью | presigned-ссылки старого ключа умирают (живут 5 мин) |
| OpenAI / Anthropic | `AI_OPENAI_API_KEY`, `AI_ANTHROPIC_API_KEY` | консоль провайдера → новый ключ в проекте окружения, старый Revoke | `cli ai-smoke` | Лимиты расходов проекта сохраняются |
| Sentry DSN | `SENTRY_DSN` | Sentry → Client Keys → новый, старый Disable | тестовое событие | — |
| PostHog | `ANALYTICS_POSTHOG_API_KEY` | PostHog → Project API key → Reset | событие доходит | — |
| PostHog personal API key | `ANALYTICS_POSTHOG_PERSONAL_API_KEY` (только `backend/.env` владельца) | PostHog → Account settings → Personal API keys → Roll | `make cli ARGS=posthog-dashboard` показывает план | На серверах ключа нет: он нужен только для дашборда как кода (6.6) |
| Пароли pgBackRest | `repo1-cipher-pass`, `repo2-cipher-pass` | **только новым репозиторием**: `stanza-create` в новый путь, полный бэкап, старый репозиторий хранится до конца PITR (14 дней) | `pgbackrest info`, restore-test | Шифрование репозитория не перешифровывается на месте |
| Deploy SSH-ключи | — | Terraform: новый ключ, `terraform apply`, старый удалить | `kamal app details` | — |
| Токены Cloudflare, Hetzner, GitHub | секреты CI | в консоли сервиса: новый с теми же правами, старый удалить | прогон CI / `terraform plan` | Права — минимальные (OWNER_CHECKLIST п. 5) |
| age-ключ SOPS | — | новый ключ, `sops updatekeys`, перешифровать файлы, старый удалить | `sops -d` в файл, не в терминал | — |

Переменные — как в `backend/.env.example`; если имя там другое, верно `.env.example`.

## 2. K43 перед публичным запуском

1. Ассистент готовит список: все секреты stage и prod, которые попадали в чат или вывод команд.
2. Владелец ротирует по таблице выше, в своём окне Терминала.
3. После ротации: решить, удалять ли старые транскрипты `~/.claude/projects/…` (OWNER_CHECKLIST
   п. 7); если нет — риск принят явно, в них только недействительные значения.
4. Ответ в K43: «ротировано» по каждому пункту.
