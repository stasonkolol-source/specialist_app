# Выгрузка данных пользователя по запросу

Право доступа к своим данным — ZZPL ст. 26. Срок ответа — **30 дней** с получения запроса
(ст. 21). Его можно продлить ещё на 60 дней, если до конца первых 30 сообщить пользователю
причину. В MVP выгрузка делается вручную, одной командой (ARCHITECTURE §13.4,
DEVELOPMENT_PLAN 2.12b); кнопка в приложении — v1.

## 1. Принять запрос

1. Запрос приходит в поддержку (@sosedi_support_rse, «Написать в поддержку» на S47) или в бот.
2. Данные получает только владелец аккаунта: запрос должен прийти **с того же
   Telegram-аккаунта**, которым человек входит в «Соседей». Запрос от третьего лица, с другого
   аккаунта или по почте без подтверждения — отказ с объяснением, данные не отправлять.
3. Записать обращение: дата получения, Telegram id отправителя, номер обращения. Срок ответа —
   дата получения + 30 дней.

## 2. Выгрузить

Команда принимает Telegram id (его видно в чате поддержки) или внутренний id пользователя (UUID):

```bash
# dev
make cli ARGS='export-user-data 279058397 --output /tmp/export-279058397.json --note "обращение 42"'

# stage и prod (после прод-контура 3.1): та же команда в контейнере приложения
kamal app exec -d <stage|production> \
  'python -m app.entrypoints.cli export-user-data 279058397 --note "обращение 42"' > export.json
```

- Без `--output` JSON печатается в stdout. `no such user` — аккаунта с таким id нет.
- Каждая выгрузка пишется в `platform.audit_log`: действие `privacy.user_data.exported`, id
  пользователя, список разделов и `--note`. Номер обращения в `--note` указывать всегда: по нему
  видно, зачем персонал смотрел данные.

## 3. Что в файле

`{"format": 1, "user_id", "exported_at", "sections": {…}}` — по разделу на модуль:

| Раздел | Что внутри |
|---|---|
| `identity` | аккаунт, способы входа, сессии (без токенов), ограничения, согласия, роли, история статусов, запросы на удаление, блокировки |
| `specialists`, `pricing` | профиль, категории, районы, портфолио; позиции прайса |
| `jobs` | заявки клиента с фото и историей; скрытые и сохранённые; отклики, шаблоны и приглашения исполнителя |
| `messaging` | диалоги, участие, свои сообщения, обмены контактами |
| `deals`, `reviews` | сделки, их история и споры; отзывы пользователя и о нём |
| `moderation` | жалобы пользователя, санкции, кейсы о нём (решение, причина, даты) |
| `notifications`, `search`, `growth` | каналы, настройки, лента и доставки; избранное; атрибуция |
| `media` | записи о файлах и `links` — ссылки на фото и видео |

Время — UTC, суммы — в пара (1/100 динара).

Не выгружаются: сообщения собеседника (это его данные), заметки модераторов и доказательства из
кейсов, сигналы риска (антифрод), хэши токенов и служебные поля.

Ссылки на файлы (`media.links`) подписаны и **живут 24 часа**: отправлять файл сразу после
выгрузки. Истекли — выгрузить заново.

## 4. Отправить

1. Отправить JSON файлом в тот же чат поддержки, откуда пришёл запрос. В подписи — что в файле
   и что ссылки на фото работают сутки.
2. Удалить локальную копию (`rm export*.json`). Не пересылать в другие чаты, не хранить в облаке.
3. Закрыть обращение с датой ответа.

## Если что-то пошло не так

- Команда упала — повторить. Ошибка повторяется — смотреть Sentry и лог, эскалация владельцу.
  Срок 30 дней от этого не сдвигается: если он под угрозой, сообщить пользователю о продлении.
- Пользователь просит исправить данные — он правит их сам в профиле (S34) и настройках; что
  нельзя исправить в приложении — эскалация владельцу.
- Пользователь просит удалить данные — [deletion-request.md](deletion-request.md).
